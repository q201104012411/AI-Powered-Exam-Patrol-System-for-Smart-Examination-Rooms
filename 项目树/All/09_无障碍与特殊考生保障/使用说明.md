# 09 无障碍与特殊考生保障 · 使用说明

面向三类人：

- **考务/监考人员**：考试当天怎么把特殊考生送进考场（第二节）
- **考点管理员**：上线前怎么配通道、建档、演练、做算法分层测试（第三节）
- **验收/审计人员**：证据在哪、指标怎么算、怎么复核（第四、五节）

## 一、快速开始

| 我要…… | 双击 | 说明 |
| --- | --- | --- |
| 打开界面 | `启动.bat` | **默认不显示命令行黑窗口**（走 pythonw.exe）；零第三方依赖，不用 pip 安装 |
| 打开界面（连"闪一下"都没有） | `无窗口启动.vbs` | VBScript 启动，全程不创建控制台窗口 |
| 看 Python 报错（调试） | 命令行 `启动.bat console` | 保留黑窗口；等价于 `python app.py` |
| 先看效果 | `一键演示.bat` | 往 `%TEMP%\acc09_demo` 造演示数据并启动，**不动真实数据** |
| 跑自检 | `运行自检.bat` | 默认临时目录；`运行自检.bat real` 真实数据只读体检 |
| 只造演示数据 | `工具_演示数据.py --home %TEMP%\acc09_demo --yes` | 所有演示记录 `source=demo`，界面/报告写明"演示" |

> 无窗口启动失败**不会静默**：异常会写进 `data\logs\app_console.log`，并弹窗告诉你日志在哪。
> 若双击后界面没出现，先看这个日志文件。

界面有七个页签：**概览 / 无障碍通道 / 特殊考生档案 / 替代核验 / 算法公平性 / 演练与台账 / 联动与验收**。
「概览」页的指标与验收报告是同一套算法，数字不会对不上。

命令行也全能干（与 01/02/03/06 同一套协议）：

```bat
python integration_api.py --op status --args "{}"
python integration_api.py --op metrics --args "{}"
python integration_api.py --op report  --args "{}"      :: 生成验收证据（md + csv）
python linkage_bridge.py --probe                        :: 只读探测联动（不写对端数据）
python linkage_bridge.py --probe --write                :: 允许往 03 写一条测试告警
```

## 二、考试当天：把特殊考生送进考场（现场操作手册）

> 铁律：**任何情况下不得因设备原因拒绝考生入场**。设备不行就换人工，人工结论与智能核验同等效力。

### 场景 A：人脸核验失败（面部术后 / 严重痤疮 / 面部遮挡）

1. 换通道复验一次（`替代核验`页，方式选 `换设备/换通道复验`）——很多失败是角度/反光问题。
2. 仍失败 → 方式改选 `双证人工比对` 或 `双人见证原件核对`：
   - 填 **双证比对**：身份证、准考证逐项选「一致/不一致/未提供」；
     系统要求**至少 2 项一致且必须包含身份证/准考证/护照**，否则不给"通过"。
   - 填 **主检人** 与 **见证人**：两人必须不同（系统会拦住"自己见证自己"）。
   - 耗时秒数如实填（超过 3 分钟会被标记"超时"，进入整改清单）。
3. 结论选「**通过（准予入场）**」——该记录带 `等价=是` 标记，**与智能核验同等效力**。
4. 点了"登记受阻事件"的话，系统会自动开一条**因技术原因受阻**事件；核验通过后自动闭环为
   "替代通道入场"。**只要最终入场了，指标里"未能入场"就是 0。**
5. 该事件同时会推到 **03 智能终端**（红色：`ACCESS_TECH_BLOCK`），指挥中心立刻看得见。

### 场景 B：轮椅 / 肢体障碍考生

- 走 **无障碍专用通道**（台账里净宽 ≥900mm、回转 ≥1500mm、低位终端 ≤1100mm 且高度可调）。
- 若低位终端不可用：这正是要登记的受阻原因（症状选「低位终端缺失/高度不可调」），
  立即改用人工核验通道 + 专人协助，**先把人送进去，再整改设备**。
- 措施「加宽通道/轮椅通行」「低位核验终端」在 `特殊考生档案` 页点「已落实」时**必须填责任人**，
  否则系统不认（报告里的落实率要站得住）。

### 场景 C：听力障碍考生

- 用**文字/大字提示**（不能只靠语音播报）。通道台账里"文字提示"没勾的通道会被判不合格。
- 语音提示失效时登记受阻（症状「语音提示失效」），改由监考员书面提示 + 震动提示。

### 场景 D：佩戴医疗器械 / 体内植入 / 孕妇

- 走 **06 智能安检的人工安检通道**（凭医疗证明放行），本模块负责在档案里把
  「人工安检替代通道」「凭医疗器械证明放行」标记为已落实。
- 06 上报的 `SECURITY_SPECIAL_CHANNEL` 告警可以在 `联动与验收` 页对账，确认"档案说安排了，
  现场真的走了人工通道"。

### 场景 E：未取得单独同意的考生

- 直接建档，**不勾"单独同意"**：系统自动判定为"不采集人脸"，只安排人工核验通道，
  并给出合规提示。**不会、也不允许因为"没同意"而拒绝入场。**

## 三、上线前：考点管理员要做的五件事

1. **登记通道**（`无障碍通道`页）：每个考点至少三类通道各一条；无障碍通道填**现场实测**的净宽、
   回转空间、低位终端台面高度、语音/文字/震动提示。保存时系统逐条校验，不合格会列出 error
   （净宽 <900mm、回转 <1500mm、缺低位终端、台面 >1100mm、缺文字提示、降级可用却只有一种提示方式…）。
   **允许保存但要整改** —— 现场就是这样，先如实记录。
2. **建档**（`特殊考生档案`页）：按考生填报的需求类型建档，系统自动推荐保障措施
   （视力→语音引导+专人护送；轮椅→加宽通道+低位终端；听力→文字+震动；面部异常→人工核验+备案免核验…）。
   措施逐项走"申请→审批→落实（责任人+位置）"。
3. **算法分层测试**（`算法公平性`页）：上线前按性别/年龄段/眼镜/口罩录入各分层样本数与通过数。
   - 组间通过率最大差 >5% → 判"超差"，**必须选补偿策略并写说明**（调阈值 / 补样本重训 /
     该分层优先人工核验），否则系统给"不合规"提示。
   - 调完再测一次，报告里会出现"整改前后对比"，这就是评审要的"差异分析与阈值调整说明"。
   - 单组样本 <20 会被标注"样本不足，结论仅供参考"。
4. **演练**（`演练与台账`页）：每考期每考点至少 1 次。演练记录里**发现问题就必须写整改措施**，
   否则系统拒绝保存；判"不合格"的演练必须写重演计划。演练到位，指标里的"替代通道可用性"才算 100%。
5. **出报告**（`联动与验收`页 → 生成验收报告）：产出 Markdown 报告 + 指标 CSV + 脱敏台账 CSV，
   落在 `data\reports\` 与 `data\ledgers\`。

## 四、联动怎么用（与 00/01/02/03/06 的关系）

- 09 **不改** 任何其它专题的文件；它在内存里把自己注册进 00 的联动总线（`PROJECTS["09"]`），
  因此**别的专题也能按同一协议调 09**。
- `联动与验收`页可以：
  - 看各专题是否可达（不可达会显示具体原因，不假装成功）；
  - 点「全链路探测」逐项验证：00 总线 → 各专题 → 09 经总线调自己 → 02 画质 → 03 推送 → 03 复核 →
    06 概览与人工安检通道对账。**探测默认只读**，若要往 03 写一条测试告警需显式勾选。
  - 点「补发待发事件」把 03 不可达期间攒下的事件补发出去。

几个必须知道的联动行为：

| 情况 | 系统的行为 |
| --- | --- |
| 01 人脸核验不可用（如特征索引未建） | 如实返回不可用；替代核验照常走通 —— **算法不行不等于考生不能入场** |
| 02 说该机位画质可信度低 | 核验结论标注降权、优先人工核验；09 推的**人工确认**告警不因画质被降级（但会把可信度写进详情） |
| 03 不可达（断网/终端没开） | 事件进本地 `outbox` 队列，界面显示"待重发"，网络恢复后一键补发，**事件不丢** |
| 09 推了红色告警 | 03 要求"先人工确认再复核"，09 不去绕过；橙色告警可直接复核结案并留痕 |
| 06 上报特殊考生人工安检通道 | 09 只读 03 的告警做对账，用来核对档案与现场是否一致 |

## 五、验收/审计怎么核对

1. **指标**：`概览`页与报告"一、关键指标达标情况"用同一口径；报告里 `未达标` 会点名。
2. **证据链**：
   - 通道尺寸与校验 → 报告"二、通道配置" + 通道明细表；
   - 建档与措施落实 → 报告"三、特殊考生档案与保障措施" + 脱敏台账；
   - 替代核验（双证/双人见证/等效性）→ 报告"四、替代核验" + 制度声明；
   - 受阻与未入场 → 报告"五、因技术原因入场受阻事件"（**未入场会原样列出，不粉饰**）；
   - 算法公平性 → 报告"六、算法公平性分层测试"（含整改前后对比）；
   - 演练 → 报告"七、演练记录"；
   - 联动留痕 → 报告"八、联动留痕"（含 outbox 与审计链结论）。
3. **留痕不可抵赖**：本模块的审计是**哈希链**（`prev_hash → this_hash`），
   改一条就会断链。`status` 接口与报告都会给出链校验结论。
4. **脱敏**：台账/报告默认脱敏（证件号留后 4 位、姓名留姓），医疗证明编号不导出。
5. **不越界的证据**：`python 自检.py` 的 [11] 组会把 00/01/02/03/06 关键文件的 SHA-256
   指纹与自检前对比，输出"指纹未变"。

## 六、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 双击 `启动.bat` 黑窗一闪 / 没反应 | 默认无窗口启动，黑窗一闪是正常的（界面随后出现）。若界面始终不出现：看 `data\logs\app_console.log`（启动异常都会写进去并弹窗提示） |
| 完全没有命令行窗口也不弹窗 | 用 `无窗口启动.vbs`；若它报英文对话框"Python not found"，说明 Python 没装或没勾 Add to PATH |
| 想看到 Python 的报错 | 命令行里跑 `启动.bat console`（或 `python app.py`） |
| 「因技术原因未能入场」指标是红的 | 有受阻事件结案为 `denied`。到 `替代核验`页的受阻事件列表里逐条看处置说明，整改后重新结案 |
| 「算法分层测试与差异」不达标 | 要么没做测试（必测分层：性别/年龄/眼镜/口罩），要么组间差 >5% 且未记录补偿策略 |
| 「替代核验通道可用性」不达标 | 该考点本考期没演练，或缺可用的人工/无障碍通道，或有判"不合格"的演练未重演 |
| 通道保存不了 | 缺考点或通道编码；另外校验不合格**不会**阻止保存，只是列出 error 要整改 |
| 措施点"已落实"被拒 | 没填责任人/岗位。这是故意的：报告里的落实率必须有主 |
| 受阻事件显示"未上报" | 03 智能终端不可达（看 `联动与验收`页原因）；网络恢复后点「补发待发事件」 |
| 红色告警复核被拒，提示"必须先确认" | 03 的强制确认机制，在 03 终端界面确认后再复核；09 不绕过 |
| 报表/台账里出现"演示"字样 | 该记录 `source=demo`，是 `工具_演示数据.py` 造的，不冒充真实记录 |
| 想看真实数据体检 | `运行自检.bat real` 或 `python 自检.py --real`（只读，不写业务数据） |

## 七、数据与合规注意事项

1. 数据默认在 `data\`，可用环境变量 `EXAM_ACCESS_HOME` 重定向（自检、演示都用它隔离）。
2. 库里有**敏感个人信息**（残障/健康）：装了 `cryptography` 自动字段级加密；
   没有则如实降级并在界面/报告写明。密钥优先取 `EXAM_DATA_KEY`，否则用 `data\.data_key`
   —— **丢失密钥即无法恢复已加密数据，请备份**。
3. `data\` 下的库、报告、台账导出都属于考生数据，**不要提交到公开仓库**。
4. 台账导出默认脱敏；确需明文导出要显式关掉脱敏，并注意保密。
5. 保留期建议按最小必要执行（`storage.purge_runtime(keep_days)` 清运行态数据，**审计不删**）。
