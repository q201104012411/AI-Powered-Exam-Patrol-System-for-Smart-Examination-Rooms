# 摄像头 AI 识别

只做两件事：**摄像头添加管理** + **AI 框架识别**。
**没有登录、没有口令、没有角色权限**——双击 `启动.bat`，打开即用。

> 需要账户与权限体系的是 01 人脸核验 / 02 摄像头核查 / 03 智能终端那几套；
> 本目录是纯工具，刻意不掺和权限，避免"想看个画面还得先登录"。

## 一、快速开始

```
1) 双击「安装环境.bat」        # 只装 opencv-python 4.x + numpy + Pillow
2) 双击「启动.bat」            # 打开界面（无登录）
3) 「① 摄像头管理」→ 填个名字 → 地址下拉里选（启动时会自动扫描本机摄像头）
   → 点「➕ 添加」
4) 切到「② AI 识别」→ 点「🔄 重新加载」
```

启动时程序会**自动扫描本机摄像头**并填进地址下拉，所以通常只需要：
**填名字 → 选地址 → 添加**。

## 二、界面只有两个页签

### ① 摄像头管理（刻意做得极简）

添加摄像头只要两项：

| 字段 | 说明 |
| --- | --- |
| **名字** | 随便起，例如"1考场正门" |
| **地址** | 从下拉里选；下拉内容是自动扫描到的本机摄像头 + 「本地视频文件…」 |

| 按钮 | 作用 |
| --- | --- |
| ➕ 添加 | 按名字+地址新增一路 |
| 💾 保存修改 | **双击表格行**载入后，改完点它保存 |
| 🗑 删除 | 删除选中行（会先停掉它的取流） |
| 🔍 扫描 | 重新扫描本机摄像头，刷新下拉候选 |
| ✖ 取消编辑 | 退出编辑状态、清空输入 |

**地址下拉的三种来源**：

| 来源 | 例子 | 说明 |
| --- | --- | --- |
| 自动扫描到的本机摄像头 | `0`、`1` | 启动/点扫描时自动填进下拉 |
| 本地视频文件… | `D:\videos\room1.mp4` | 选它就弹文件框，没有摄像头时也能演示 |
| 手工输入（下拉框可打字） | `rtsp://192.168.1.64:554/Streaming/Channels/101` | 网络摄像头，直接粘地址即可 |

> 同一地址不能登记两次，会明确拒绝。

### ② AI 识别

- 多路网格，每路显示：画面 + 彩色框 + 中文标签（`#编号 行为`）+ 人数/越界/FPS。
- 框的颜色含义：**绿=正常，橙=异常行为，红=越界/贴边**。
- 顶部「检测模式」：`standard`(分析长边 640) / `dense`(768) / `energy`(416)。
  算力紧张选节能；40 人考场选密集。
- 顶部会**如实显示当前检测链**：正常为 `检测链：YOLO11n-ONNX（主力检测器）`；
  模型或依赖缺失时显示 `检测链：HOG+SVM（YOLO11n 模型不可用）`，
  同时把检测链名字写进 `data\ai_backend.txt`。

### ③ 手机识别（**该能力已下线**）

**2026-10-14 模型层整体替换为「YOLO11n ONNX 版」后，手机识别随之下线**：
新检测链只解码 COCO 的 `person` 类，不再解码 cell phone，界面上不再有手机框、
手机告警，也没有手机峰值诊断项。手机识别需接入项目里已有的
**06_智能安检与手机作弊器材检测**模块。

旧版曾解码 cell phone 类，但**从来没达到可用水平**——历史实测（2026-10）仍然成立：

| 实测样本 | 手机类峰值置信度 |
| --- | --- |
| 真实照片（COCO，确知画面里有手机） | **0.0001 ~ 0.0007** |
| 把手机区域裁切放大 4 倍后再测 | **0.005** |
| 合成"清晰手机"（占画面宽 12%、高 36%） | **0.001** |
| 输入分辨率 640 / 960 / 1280 三档 | 全部 ≈ 0，**与分辨率无关** |

结论：**`yolo11n` 的 cell phone 类对"考场里学生手上的手机"基本无响应**，
调阈值救不回来（0.001 与 0.60 之间差两个数量级）。

要做到能用的手机识别，可行方向（按性价比排序）：
1. **用考场实拍照片微调一个专用模型**（把"手机"当成自定类训练），
   这是唯一可能达到考场可用精度的路线；
2. 换更大的通用模型（`yolo11s/m`）——**可能性存疑，未实测**；
3. 接入**已有的 06_智能安检与手机作弊器材检测**模块——
   那里本就专做这件事，比在通用检测模型上硬凑更对口。

> 上面这些数据的原始记录（当时的样本、命令与结论）见
> [`识别准确率优化报告.md`](识别准确率优化报告.md) 第四节，已作为历史记录原样保留。

**生成 / 更换模型**（两条路径任选其一，产物都是 `models\yolo11n.onnx`）：

```bat
:: ① 本机重新导出（从仓库附带的 models\yolo11n.pt；需先 pip install ultralytics onnxslim）
python 工具_YOLO模型导出.py

:: ② 从 ultralytics 官方 release 下载预导出 onnx（带 SHA256 校验）
python 下载模型.py --check      :: 检查已有模型是否完整
python 下载模型.py --list       :: 看有哪些可下载
python 下载模型.py              :: 下载默认的 yolo11n.onnx
```

- ① 导出参数固定 `imgsz=640 / opset=12 / simplify=True`；改脚本里的 `MODEL_NAME`
  可换成 `yolo11s` 等；
- ② 只提供 `yolo11n.onnx` / `yolo11s.onnx` 两个**检测**模型，没有姿态模型；
- **本地导出的 onnx 哈希与官方 release 不同属正常**，能正常推理即可。

### 检测到的行为

| 行为 | 依据 | 需要模型吗 |
| --- | --- | --- |
| 越界 / 贴边 | 框心越过警戒线、或贴到画面边缘 | 否 |
| 起立/站立 | 框高 > 55% 且越过警戒线且**头顶在画面上部** | 否 |
| 前倾/趴桌、大幅度偏转 | 框宽高比与高度变化（连续多帧确认） | 否 |
| 东张西望、长时间低头 | 质心横向摆动 / 框高持续变矮 | 否 |
| 坐下 | 框较矮且位于画面下半 | 否 |
| 转脸偏头 / 闭眼趴睡 / 眼神游移 | Haar 人脸+人眼级联 | 否（OpenCV 自带） |
| ~~使用手机~~ | **该能力已下线**（新检测链只解码 person 类），需接入 06 模块 | — |

## 三、让识别更准（可选，不放也能跑）

检测链**固定优先级、自动选择**，找到哪个用哪个；
**界面与配置都无法指定后端族**：

| 优先级 | 检测器 | 需要的文件 | 能拿到什么 |
| --- | --- | --- | --- |
| 1 | **YOLO11n ONNX**（主力） | `models\yolo11n.onnx` | 人框（只解码 COCO `person` 类） |
| 2 | MobileNet-SSD | 本目录 `MobileNetSSD_deploy.prototxt` + `.caffemodel` | 人框 |
| 3 | HOG+SVM（兜底） | 无需文件，OpenCV 自带 | 人框 |

模型放到 `models\` 即自动启用，不用改代码；YOLO 模型路径可用环境变量
`EXAM_YOLO_MODEL` 覆盖，输入固定 640×640。

- **YOLO 可用时，某帧零检出会再叠加一次 HOG 兜底并合并结果**，避免整帧漏人。
- `EXAM_YOLO_DISABLE=1` 强制禁用 YOLO（对比 / 排查用），退回 HOG+SVM。
- `EXAM_YOLO_EP=coreml` 时优先 CoreML（失败自动回退 CPU）。
- 同一个人被检成"头/上半身 + 整体"时会**自动去重**（只留整体框）；Haar 人头与背景差分
  改成**只在主链零检出时兜底**，所以单人画面不会画出一堆框。

> **如实说明**：
> 1. 仓库**已附带 `models\yolo11n.onnx`**（Ultralytics 官方 YOLO11n COCO 检测模型导出，
>    opset 12 / simplify=True，10,741,326 字节），所以默认走的是 **YOLO11n** 而不是 HOG；
>    另有 `models\yolo11n.pt`（5,613,764 字节，官方权重）供离线重新导出。
> 2. 检测链依赖 **`onnxruntime`**；未安装时**静默回落 HOG+SVM**，**不报错、不崩溃**，
>    界面顶部会如实显示为 HOG+SVM。
> 3. 逐人信息字段：`pid / rect / action / bad / crosses / behaviors / density_level`。

### 设置文件 `data\ai_settings.json`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `ai_mode` | `standard` | `standard`(640) / `dense`(768) / `energy`(416) |
| `ai_input_dim` | `0` | 直接指定分析长边；`0`=按 `ai_mode` 取预设 |
| `yolo_model_path` | 空 | 显式指定 YOLO 的 onnx；空=自动用 `models\yolo11n.onnx` |
| `yolo_conf` | `0.25` | YOLO 置信度阈值 |
| `yolo_iou` | `0.45` | YOLO 后处理 NMS 的 IoU 阈值 |
| `yolo_input_dim` | `640` | YOLO 输入边长（官方导出固定 640） |
| `boundary_pct` | `92` | 警戒线位置（画面高度百分比） |

> 检测链由代码自动选择，设置里没有"指定后端族"的开关；
> 旧版的后端族 / GPU / 姿态骨架相关设置键已全部移除。

## 四、数据放在哪

默认本目录 `data\`，可用环境变量 `EXAM_AI_CAM_HOME` 或同目录 `ai_cam_home.txt` 重定向。

| 路径 | 内容 |
| --- | --- |
| `data\cameras.db` | 摄像头台账（SQLite，一张表） |
| `data\ai_settings.json` | AI 识别设置 |
| `data\ai_backend.txt` | 当前实际用的检测链（如实记录） |
| `data\logs\` | 取流日志（打开失败/重连都有据可查） |
| `data\hide_cmd.on` | 存在则用 pythonw 零黑窗口启动 |

## 七、注意事项

1. **取流永不卡界面**：打开带超时、读取带看门狗、释放异步。地址写错只会让那一路
   显示"重连中"，其他路和界面都不受影响。
2. **同一摄像头别开两处**：Windows 上本机摄像头被别的程序（或本程序另一路）占用时，
   会读不到画面并报"设备被占用"。
3. **RTSP 建议用子码流**：主码流 1080p 多路解码很吃 CPU，识别用子码流（如 640×480）足够。
4. **不落全量视频、不自动抓拍**：本目录只在内存里处理画面，不做录像，也不会偷偷存图。
5. **本目录不参与 01/02/03 的权限与审计**，是独立工具。
