# 摄像头 AI 识别

只做两件事：**摄像头添加管理** + **AI 框架识别**。
**没有登录、没有口令、没有角色权限**——双击 `启动.bat`，打开即用。

> 需要账户与权限体系的是 01 人脸核验 / 02 摄像头核查 / 03 智能终端那几套；
> 本目录是纯工具，刻意不掺和权限，避免"想看个画面还得先登录"。

## 一、快速开始

```
1) 双击「安装环境.bat」        # 只装 opencv-python 4.x + numpy + Pillow
2) 双击「启动.bat」            # 打开界面（无登录）
3) 「① 摄像头管理」→ 填个名字 → 地址下拉里选（启动时会自动扫描本机摄像头）
   → 点「➕ 添加」
4) 切到「② AI 识别」→ 点「🔄 重新加载」
```

启动时程序会**自动扫描本机摄像头**并填进地址下拉，所以通常只需要：
**填名字 → 选地址 → 添加**。

## 二、界面只有两个页签

### ① 摄像头管理（刻意做得极简）

添加摄像头只要两项：

| 字段 | 说明 |
| --- | --- |
| **名字** | 随便起，例如"1考场正门" |
| **地址** | 从下拉里选；下拉内容是自动扫描到的本机摄像头 + 「本地视频文件…」 |

| 按钮 | 作用 |
| --- | --- |
| ➕ 添加 | 按名字+地址新增一路 |
| 💾 保存修改 | **双击表格行**载入后，改完点它保存 |
| 🗑 删除 | 删除选中行（会先停掉它的取流） |
| 🔍 扫描 | 重新扫描本机摄像头，刷新下拉候选 |
| ✖ 取消编辑 | 退出编辑状态、清空输入 |

**地址下拉的三种来源**：

| 来源 | 例子 | 说明 |
| --- | --- | --- |
| 自动扫描到的本机摄像头 | `0`、`1` | 启动/点扫描时自动填进下拉 |
| 本地视频文件… | `D:\videos\room1.mp4` | 选它就弹文件框，没有摄像头时也能演示 |
| 手工输入（下拉框可打字） | `rtsp://192.168.1.64:554/Streaming/Channels/101` | 网络摄像头，直接粘地址即可 |

> 同一地址不能登记两次，会明确拒绝。

### ② AI 识别

- 多路网格，每路显示：画面 + 彩色框 + 中文标签（`#编号 行为`）+ 人数/越界/FPS。
- 框的颜色含义：**绿=正常，橙=异常行为，红=越界/贴边**；**手机=橙色粗框并标「手机」**
  （未归属到具体人的手机会单独画框标「检测到手机」）。
- 顶部「检测模式」：`standard`(分析长边 640) / `dense`(768) / `energy`(416)。
  算力紧张选节能；40 人考场选密集。
- 顶部会**如实显示当前检测后端与手机识别是否可用**，同时写 `data\ai_backend.txt`。

### ③ 手机识别（考场违规使用手机）

学生手上/桌上有手机时，会把手机框出来，并把「使用手机」并入该人的行为，
底部状态栏出现 `⚠ 手机 N`。

**手机只能靠模型检出**：HOG 是行人检测器、Haar 是人脸级联、MobileNet-SSD 只有 20 类，
**三者都不认手机**。所以本功能依赖 YOLO 模型，仓库里已附带：

```
models\yolo11n.onnx       10.9 MB  官方预导出，含 COCO 的 cell phone 类
```

- **已随仓库提供**，clone 下来即可用，不用自己转换；
- 来源是 [ultralytics 官方 release](https://github.com/ultralytics/assets/releases)，
  下载后按官方公布的 SHA256 逐字节校验；
- 没放模型时状态栏会明确写「手机识别需模型」，**不会假装检过**。

想换更大/更准的模型，或用姿态模型（骨骼点判行为更准）：

```bat
python 下载模型.py --check      :: 检查已有模型是否完整
python 下载模型.py --list       :: 看有哪些可下载
python 下载模型.py --pose       :: 额外下载姿态模型
```

### 检测到的行为

| 行为 | 依据 | 需要模型吗 |
| --- | --- | --- |
| 越界 / 贴边 | 框心越过警戒线、或贴到画面边缘 | 否 |
| 起立/站立 | 框高 > 55% 且越过警戒线且**头顶在画面上部** | 否 |
| 前倾/趴桌、大幅度偏转 | 框宽高比与高度变化（连续多帧确认） | 否 |
| 东张西望、长时间低头 | 质心横向摆动 / 框高持续变矮 | 否 |
| 坐下 | 框较矮且位于画面下半 | 否 |
| 转脸偏头 / 闭眼趴睡 / 眼神游移 | Haar 人脸+人眼级联 | 否（OpenCV 自带） |
| **使用手机** | YOLO 检出 cell phone 并与人体框关联 | **是（必须放模型）** |

## 三、让识别更准（可选，不放也能跑）

检测后端按优先级**自动选择**，找到哪个用哪个：

| 优先级 | 后端 | 需要的文件 | 能拿到什么 |
| --- | --- | --- | --- |
| 1 | **YOLO-pose** | `yolo11n-pose.onnx` | 人框 + 17 骨骼点 |
| 2 | **YOLO**（仓库已附带） | `models\yolo11n.onnx` | 人框 + **手机等 80 类** |
| 3 | MobileNet-SSD | `MobileNetSSD_deploy.prototxt` + `.caffemodel` | 人框（无手机类） |
| 4 | HOG+SVM（兜底） | 无需文件，OpenCV 自带 | 人框（无手机类） |

模型放到**本目录**或**本目录 `models\`** 即自动启用，不用改代码。
放了 pose 模型后画面会多画一层**青色骨架**，并用骨骼几何判低头/偏头/趴桌。

> **如实说明**：
> 1. 仓库**已附带 `models\yolo11n.onnx`**（官方预导出、SHA256 校验），所以默认走的是
>    **YOLO** 而不是 HOG——手机识别也依赖它。
> 2. **cv2.dnn 装不了 YOLO11 的 ONNX**（实测 OpenCV 4.14 在 Concat 节点报形状错误），
>    程序会**自动改用 onnxruntime**（装了 opencv-python 的机器通常已有），无需你干预；
>    两者都失败才回退 HOG。
> 3. 手机阈值默认 0.60（比人的 0.30 更严）：实测手机类在无关画面里会刷出
>    置信度约 0.50 的候选，阈值放宽就会满屏假手机。

### 设置文件 `data\ai_settings.json`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `ai_mode` | `standard` | `standard`(640) / `dense`(768) / `energy`(416) |
| `ai_input_dim` | `0` | 直接指定分析长边；`0`=按 `ai_mode` 取预设 |
| `model_kind` | `auto` | `auto` / `yolo` / `caffe` |
| `model_path` | 空 | 显式指定模型文件 |
| `prefer_gpu` | `true` | 有 CUDA 版 OpenCV 时走 GPU |
| `use_onnxruntime` | `false` | 装了 `onnxruntime-gpu` 可走独显 |
| `yolo_conf` | `0.30` | YOLO 置信度阈值 |
| `boundary_pct` | `92` | 警戒线位置（画面高度百分比） |
| `draw_pose` | `true` | 有骨骼点时是否画骨架 |

## 四、数据放在哪

默认本目录 `data\`，可用环境变量 `EXAM_AI_CAM_HOME` 或同目录 `ai_cam_home.txt` 重定向。

| 路径 | 内容 |
| --- | --- |
| `data\cameras.db` | 摄像头台账（SQLite，一张表） |
| `data\ai_settings.json` | AI 识别设置 |
| `data\ai_backend.txt` | 当前实际用的检测后端（如实记录） |
| `data\logs\` | 取流日志（打开失败/重连都有据可查） |
| `data\hide_cmd.on` | 存在则用 pythonw 零黑窗口启动 |

## 七、注意事项

1. **取流永不卡界面**：打开带超时、读取带看门狗、释放异步。地址写错只会让那一路
   显示"重连中"，其他路和界面都不受影响。
2. **同一摄像头别开两处**：Windows 上本机摄像头被别的程序（或本程序另一路）占用时，
   会读不到画面并报"设备被占用"。
3. **RTSP 建议用子码流**：主码流 1080p 多路解码很吃 CPU，识别用子码流（如 640×480）足够。
4. **不落全量视频、不自动抓拍**：本目录只在内存里处理画面，不做录像，也不会偷偷存图。
5. **本目录不参与 01/02/03 的权限与审计**，是独立工具。
