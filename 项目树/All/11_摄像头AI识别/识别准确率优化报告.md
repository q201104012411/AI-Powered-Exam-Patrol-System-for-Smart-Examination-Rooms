## 一、问题 1：正常坐着被判「越界」

### 现象
用户正常坐在座位上，界面显示「越界 1」，画面被标红。

### 根因（实测确认）
原判据是 **"人框底边越过警戒线"**，而这个人框（Haar 人脸按人体比例推算）
本身就延伸到画面底部，导致**只要画面里有人，框底就必然压线**：

| 警戒线位置 | 实测结果 |
| --- | --- |
| 92%（界面默认） | 越界 |
| 98%（用户后来调的） | **仍然越界** |

也就是说，把警戒线往下挪**根本没用**——因为人框底就在 98% 以下。
这条判据与"站/坐"无关，等价于"画面里有人就报越界"。

### 修改
越界 = **框底越过警戒线** 且 **头顶已下移到画面下部**（`HEAD_LOW_RATIO = 0.45`）。

真越界的语义是"走到镜头前 / 离开座位"，那种情况下**头顶也会明显下移**：

| 姿态 | 头顶占画面高 |
| --- | --- |
| 站立（远处） | 约 20% |
| 坐姿（近景） | 约 28% |
| 走到镜头前 | > 45% |

### 改后实测

| 场景 | 框底过线 | 头顶占比 | 判定 |
| --- | --- | --- | --- |
| 坐姿近景 | 否 | 12% | 不越界 ✅ |
| 坐姿略前倾 | 否 | 35% | 不越界 ✅ |
| **走到镜头前** | **是** | **50%** | **越界 ✅** |
| 趴到桌上 | 是 | 69% | 越界 ✅ |

坐姿误报消失，真越界仍能报出。

## 二、问题 2：坐着不动被判「大幅度偏转」

### 现象
用户坐着不动，标签显示「大幅度偏转」。

### 根因（实测确认）
偏转判据用的是**固定宽高比阈值 0.85**。而实测这个坐姿人框的宽高比是：

```
框 = 298 × 215  ->  宽高比 = 1.386
```

**1.386 远大于 0.85，坐着必然触发。** 固定阈值根本无法同时适配站/坐、远/近。

### 修改
改为**相对本轨迹自身历史**的自适应判据：

- 偏转 = 宽高比 > 该轨迹历史中位数 × `1.15`
- 前倾 = 宽高比 > 该轨迹历史中位数 × `1.08`
- 另加绝对下限 `1.6`：宽高比到 1.6:1 已是明确侧身形态，直接判偏转
  （避免"基线本来就宽"的人漏报）

### 改后实测（连续 4 帧确认）

| 场景 | 基线 | 当前 | 偏转阈值 | 判定 |
| --- | --- | --- | --- | --- |
| 正常坐姿（不变） | 1.39 | 1.39 | 1.59 | 正常姿态 ✅ |
| 轻微侧身 +8% | 1.39 | 1.50 | 1.59 | 不报（属合理正常） |
| **明显侧转 +30%** | 1.39 | 1.80 | 1.59 | **报偏转 ✅** |
| **远距离侧转** | 0.55 | 0.80 | 0.63 | **报偏转 ✅**（旧逻辑会漏） |
| 前倾趴桌 +12% | 1.39 | 1.55 | 1.59 | 不报（未达阈值） |

**旧逻辑下前两行走会误报、第四行走会漏报；新逻辑四行判定都合理。**

## 三、问题 3：界面满屏重叠框（此前已修，此处归档）

单人场景曾显示「14 人、越界 7」，框和标签叠成一团。根因是辅助检测器持续产出
虚警、每个框都开一条轨迹。已改为：按来源可靠性去重（IoU 超阈值**或框心落在已保留框内**
即丢弃）、低可靠来源须与已有框重叠才采纳、平坦区域（墙/幕布）否决、标签避让。

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 14 个重叠脏候选 | 14 | **1** |
| 空场景孤立虚警 | 3 | **0** |
| 标签重叠对数 | 必然 >0 | **0** |

## 四、手机识别：实测判定「不可用」（如实记录）

> 上一轮我曾声称"手机识别已实现"。**这是过度声称，现予以纠正。**

用户反馈"没有出现手机"。查得两层原因：

**原因 A（已修）**：02 目录下**没有模型**，走的是 HOG+SVM，而
HOG / Haar / MobileNet-SSD **都不认手机**。
（证据：02 的 `data\ai_backend.txt` 写着 `HOG+SVM(CPU)`，时间早于模型下载时间。）

**原因 B（本质，无法用调参解决）**：即使模型到位，`yolo11n` 也认不出考场里的手机。

用**确知画面里有手机**的样本实测手机类峰值置信度：

| 样本 | 手机类峰值置信度 |
| --- | --- |
| 真实照片（COCO，确知有手机） | **0.0001 ~ 0.0007** |
| 手机区域裁切放大 4 倍 | **0.005** |
| 合成"清晰手机"（占画面宽 12%、高 36%） | **0.001** |
| 输入分辨率 640 / 960 / 1280 | 全部 ≈0，**与分辨率无关** |

**结论**：`yolo11n` 的 cell phone 类对"考场里学生手上的手机"基本无响应，
与阈值无关（0.001 与阈值 0.60 差两个数量级）。**调参救不回来。**

### 已做的处理
1. 把模型也部署到 02 与 03（此前只有 11 有）；
2. 把手机链路接进 02/03 界面（逐路「📱 手机 N」、面板边框转红、状态栏告警）；
3. 新增 **`phone_peak()` 诊断**：显示手机类峰值置信度，**不受阈值影响**。
   界面会显示「手机峰值 x.xx」——**长期是 0.0x 就说明是模型认不出，不是阈值问题**，
   以后不必再靠猜；
4. 在 02/03/11 的使用说明里明确写出这个局限，避免按"已经能抓手机"去验收。

### 要真正可用的三条路（按性价比排序）
1. **用考场实拍照片微调专用模型**（把"手机"当自定类训练）——唯一可能达到考场精度的路线；
2. 换更大通用模型（`yolo11s/m`）——**存疑且未实测**：本机下载 36MB 太慢已放弃，
   但 n 版在"手机占画面 1/8"时仍只有 0.001，仅升一号未必够；
3. **接入项目里已有的 `06_智能安检与手机作弊器材检测`**——那里本就专做这件事，
   比在通用检测模型上硬凑更对口。

**代码链路（后处理 → NMS → 与人关联 → 画框 → 告警）已完整测通**，
换一个真能认手机的 ONNX 模型即可直接生效，**不需要改代码**。
