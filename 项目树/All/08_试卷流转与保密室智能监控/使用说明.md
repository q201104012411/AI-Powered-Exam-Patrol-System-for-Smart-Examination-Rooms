# 使用说明 · 试卷流转与保密室智能监控

> 本说明面向实际使用者（考务管理人员 / 值守员 / 押运员 / 巡检人员）。
> 想看「实现了文档哪些条款、怎么验证」请看 [README.md](README.md)。

## 一、怎么启动

| 想做什么 | 双击这个 |
| --- | --- |
| 用桌面程序看监控 | `启动保密室监控界面.bat` |
| 用浏览器看监控（含手机/平板） | `启动网页版.bat` → 自动打开 http://127.0.0.1:5020/ |
| 关掉网页服务 | `停止网页版.bat` |
| 一键体检（编译 + 122 单元 + 110 自检 + 86 网页接口） | `运行自检与测试.bat` |
| 让启动器不显示黑窗口 / 改回来 | `切换命令行窗口.bat` |

启动脚本会自己找一个**装了依赖**的 Python。找不到会提示装什么。

### 默认账户（桌面端与网页版**同一份**，改一边另一边立刻生效）

| 用户名 | 默认口令 | 角色 |
| --- | --- | --- |
| `owner` | `EDY_POWERQ` | 所有者（管账户、删机位、看审计） |
| `teacher1` | `teacher1` | 管理员（日常值守作业） |

**第一件事就是改口令**：登进去 → 「系统设置」→ 修改口令。

### 隐藏命令行窗口（不显示黑窗口）

登 `owner` → 「系统设置」→ 勾选「隐藏命令行窗口」。之后双击启动脚本就零黑窗口。
想改回来：双击 `切换命令行窗口.bat`。

## 二、界面怎么用（六页签）

### 1. 实时画面 —— 看摄像头

- 上方选保密室 → 点「开始全部取流」。
- 每个机位一张画面，画面下方显示状态：`实时` / `连接中` / `画面中断` / `未取流`。
- 「抓帧留证」把当前画面存到 `data\evidence\`（带时间戳与机位号）。
- **🔥 火场识别**默认开启：多路画面在后台检测火焰/烟雾（连续帧确认，单帧不算），
  确认火警/烟雾疑似会写入下方「告警中心」（`FIRE_ALARM` 红 / `FIRE_SMOKE` 橙），
  不会打断取流；不需要时取消勾选即可。
- **本机没摄像头时**：点「探测本机摄像头」会有提示。改用：
  - 本机 USB 摄像头 → 取流地址填 `0` / `1` / `2`
  - 网络摄像头 → 填 RTSP，如 `rtsp://admin:口令@192.168.1.64:554/Streaming/Channels/101`
  - 本地视频文件 → 直接填路径（演示/联调用）

### 2. 保密室监控 —— 七项都在这

- 顶部显示该房间的**覆盖率**与**盲区朝向**；点「七项体检」出一张体检表。
- 事件注入按钮（用于演练与验收演示）：
  - **① 正常开门**（双因子 + 双人）→ 放行
  - **② 单因子开门** → 拒绝 + 告警
  - **③ 单人开门** → 拒绝 + 告警
  - **④ 未授权开门** → 红色告警（这就是 ≤5s 时延指标的样本来源）
  - **⑤ 红外/门窗磁/震动/开柜触发** → 布防时段内红色告警
  - **⑥ 试卷柜未授权开柜 / 柜内异常** → 告警
  - **⑦ 环境上报**（温度/湿度/水浸/烟感）→ 越限即告警
  - **⑧ 登记一轮巡查**（机器人值守）
  - **⑨ 生成 7 天录像段** / **⑩ 挖一个缺口** → 看连续性核查能不能报出来

### 3. 试卷流转 —— 五环节

按顺序点一遍就是一次完整演练：

1. **登记试卷袋**（编号 + RFID + 科目 + 数量 + 保密室）
2. **交接**（选两人、双签、双人脸）→ 缺任何一项会告警，这才叫"双人签字 + 人脸确认"
3. **电子铅封**（填封签号）→ 再点「上报异常开启」看告警
4. **押运**：填车牌/司机/押运员/路线 → 再点「上报位置」，
   界面上有「在路线上」和「偏离路线」两个示例按钮，直接看 ≤30s 时延指标
5. **分发至考场** → **回收与封存**（填发出/回收数量；填不一样的数会报差异）

任意时刻点「全链条追溯」，能看到这个袋经过的每个环节、每个人、什么时间。

### 4. 告警中心

- 按状态（待处置/已确认/已处置）和告警码筛选。
- 红级告警最优先；「批量确认红色」一把清掉。
- 每条都带**告警时延**（毫秒级），这正是验收指标要的证据。

### 5. 关键指标

五项指标逐条显示：**实测值 / 文档要求 / 结论**。

> 看到「**样本不足**」是正常的 —— 意思是这个指标还没有现场样本，
> **不是达标、也不是不达标**，需要现场触发后再看。

点「生成验收报告」出七章节报告；点「导出报告与台账」落到 `data\reports\` 与 `data\exports\`。

### 6. 系统设置

- 机位登记 / 修改 / 删除（删除仅 owner）
- 修改口令
- 账户管理（仅 owner）：新建、重置口令、停用、删除
- 查看审计哈希链（仅 owner / auditor）：能看到链是否完整；被改过会指出第几条
- 隐藏命令行窗口开关

## 三、数据放在哪

默认在 `08_试卷流转与保密室智能监控\data\`：

| 目录/文件 | 内容 |
| --- | --- |
| `secure.db` | SQLite：机位、门禁、入侵、试卷柜、环境、试卷袋、交接、押运、分发、回收、录像段、告警、审计 |
| `evidence\` | 告警留证截图（开柜/入侵/环境） |
| `captures\` | 巡检抓帧留档 |
| `seals\` | 电子铅封记录 |
| `handovers\` | 交接凭证 |
| `reports\` | 验收报告 |
| `exports\` | CSV 台账 |

**换盘符/换目录**：设环境变量 `EXAM_SECURE_HOME=D:\某目录`，
或在项目根目录写 `secure_home.txt`（一行，就是目标路径）。

## 四、判定逻辑速查

| 对象 | 判定 | 结果 |
| --- | --- | --- |
| **门禁** | 人脸 +（刷卡/密码）= 双因子 | 缺一 → 拒绝 + `ACCESS_DUAL_FAIL` |
| | 到场 2 人（双人双锁） | 1 人 → 拒绝 |
| | 授权但画面人数超限 | 放行 + `ACCESS_TAILGATING` |
| | 无有效双因子记录就开门 | `DOOR_OPEN_ABNORMAL`（红） |
| **覆盖率** | 6 面（前/后/左/右/上/下）每面都有配了取流地址的机位 | 覆盖率 = 满足的面数 / 6 |
| | 一台机位都没登记 | **样本不足**（不是 0% 不达标） |
| | 机位台账必拍要点缺项 | 台账问题（柜顶/柜底在 `top`/`bottom`） |
| **入侵** | 布防时段 18:00–24:00、00:00–08:00 | 时段外触发不升红 |
| **试卷柜** | 未授权开柜 / 柜内无试卷 / 被撬 | 分别告警 |
| **环境** | 温度 5–35℃、湿度 20–70%；水浸/烟感为真即报 | 越限即告警 |
| **交接** | 2 人 + 2 签字 + 2 人脸 + 扫码/RFID | 缺项分别告警 |
| **押运** | 当前位置距规划路线 > 200 米判偏离 | 即报，≤30s |
| | 车内视频 60 秒无回传 | `ESCORT_VIDEO_LOST` |
| **铅封** | 上报 broken | `SEAL_BROKEN`（红） |
| **分发** | 考场 / 数量 / 责任人 三项齐备 | 缺任何一项 → 告警 |
| **回收** | 回收数 ≠ 发出数 | `RECYCLE_COUNT_MISMATCH` |
| | 未完成封存 | `RECYCLE_MISSING` |
| **录像** | 相邻段之间缝隙超容差 | 缺口；负缝隙 → 重叠 |
| | 每机位 2 路（主/备） | 不足 → 冗余不合格 |
| | 留存期 180 天内 | 段必须加锁（WORM） |

**告警去重**：同一告警码 + 同一来源 + 同一房间 + 60 秒内，只留一条 pending，
传感器连续上报不会刷屏；**不同房间不会互相合并**。

## 六、注意事项

1. **首次登录请改口令**（尤其 owner 的默认口令）。
2. 网页版默认只监听 `127.0.0.1:5020`（本机）。要让同网段其他电脑访问，
   启动后端时加 `--host 0.0.0.0`，但**务必先改掉默认口令**，并考虑加边界防护。
3. 网页实时画面用查询串带令牌（`?token=…`），这是 MJPEG 场景的通行做法
   （`<img>` 带不了自定义请求头）；令牌是随机 32 字节、8 小时过期，只用于读画面。
4. 「事件注入」按钮是给**演练与验收演示**用的，不是真实设备上报。
5. 数据目录别手动删 `secure.db`，里面是全部台账与审计链。

## 七、接现场还需要做什么

按优先级：

1. **接摄像头**：拿到真实 RTSP 地址，逐机位填进去，把六面覆盖真的布出来
   （含柜顶、柜底 —— 这两面最容易漏）。
2. **接门禁**：把人脸终端/刷卡器的开门事件打到 `POST /api/vault/access`；
   双因子判定与告警时延就会按真实数据算。
3. **接红外/门窗磁/震动/电子锁**：事件打到 `POST /api/vault/intrusion`、
   `/api/vault/safe`；水浸/烟感/温湿度打到 `/api/vault/env`。
4. **接北斗/GPS 与车内视频**：位置打到 `POST /api/escort/position`，
   视频心跳打到 `/api/escort/video`。
5. **接录像平台**：把录像段登记进来（或定时同步），跑「录像连续性与留存配置」核查。
6. **校准时钟**：告警时延指标依赖事件时刻与服务器时钟一致，
   现场务必先做一次时间同步。
7. **积累样本后复测五项指标**：把报告里所有「样本不足」都跑出实测值。
