# 考生数据保护 · 使用说明

> 对应《考生数据保护.md》（数据分类分级 / 全生命周期控制 / 工程技术措施 /  
> 管理措施 / 考生权利响应 / 验收指标）。  
> 本目录是**可运行、可测试**的工程实现：真代码、有单元测试、有可核查的验收证据。
>
> **核心铁律**：已加密的考生数据**任何人都不能修改**，只能**删除**或**新增**。  
> 加密由 **哈希（SM3）+ 非对称签名（SM2）** 组成，任何绕过业务层的直接改库都会被验签检出。

## 五、命令行用法

所有子命令都在本目录下运行：

```bat
python cli.py summary           :: 打印摘要 + 5 项 KPI
python cli.py kpi               :: 只打印验收指标（含要求/实测/证据）
python cli.py verify            :: 校验审计哈希链（篡改会被定位到条号）
python cli.py catalog           :: 打印数据分类分级表
python cli.py permission        :: 打印角色 × 动作权限矩阵
python cli.py algorithm         :: 打印当前加密算法与密钥指纹
python cli.py report            :: 生成报告并导出（加 --stdout 可同时打印全文）
python cli.py demo              :: 生成演示数据（写入真实运行目录）
python cli.py destroy --now     :: 立即执行"到期自动销毁"
python cli.py rights --list     :: 列出权利申请台账
```

涉及写操作时，命令行同样受**权限最小化**约束：

```bat
:: 使用（目的限定：作弊判定 / 身份核验；其它一律拒绝并留痕）
python cli.py use --cand CDxxxx --purpose 作弊判定 --action 关联复核

:: 受理考生权利申请（查阅/复制/更正/删除/撤回同意）
python cli.py --confirm-risky rights --submit-cand CDxxxx --right 查阅 --verified

:: 处理权利申请
python cli.py --confirm-risky rights --handle RQxxxx --approve --result "已提供"

:: 按考生请求销毁
python cli.py destroy --by-request CDxxxx --reason "考生行使删除权"

:: 上报安全事件（要求 2 小时内上报）
python cli.py --confirm-risky incident --level S3 --title "值班终端异常"
```

全局参数：

- `--user` / `--pwd`：指定登录账户（默认 `owner`）。
- `--place` / `--device`：登录地点/终端，用于**持续校验**风险评分。
- `--confirm-risky`：高风险会话（未登记设备/地点、非工作时段）执行敏感动作的**二次确认**。
- `--db`：指定数据库路径（默认真实运行目录）。

## 七、验收指标（第六节）

运行 `python cli.py kpi`，六项指标的**要求 / 实测 / 证据**会一起打印：

1. **敏感数据加密率 100%** — 逐类别逐字段核对密文。
2. **操作审计覆盖率 100%** — 覆盖登录、查询、导出、删除、解密查看、共享、  
   登记、同意、权利申请、销毁、账户。
3. **到期自动销毁执行率 100%** — `destroys` 表（`mode=auto`）+ 审计链。
4. **越权访问测试全部拦截** — `uses` 表 `allowed=0` 记录 + 逐角色越权用例。
5. **替代通道可用性 100%** — 登记且有演练通过的通道占比。
6. **加密数据不可修改（只读）** — `signatures` 表全量验签 100% 通过，
   且试改加密字段被拒（`_readonly_probe()` 实测）。

> **"样本不足"语义**：当某项指标没有任何样本时，实测列会如实显示  
> 「样本不足」并判为**未达标**，绝不用 0 或 100% 冒充达标。  
> （例如空库时"敏感数据加密率"会显示"样本不足"，而不是 100%。）

## 八、加密、完整性与密钥

### 加密（保密性）

- **算法**：优先 **SM4-CBC + SM3**（国密，`gmssl`）；  
  库缺失时回退 **AES-256-GCM**（`cryptography`），并在报告/界面**如实标注**。  
  两条命令可核对：`python cli.py algorithm`。
- **主密钥保护**：Windows 上优先 **DPAPI**（绑定当前用户/机器），  
  否则用 Fernet；**拒绝写入明文密钥**（取不到保护后端就不落盘）。
- **密文格式**：字段级 `enc:<算法>|<...>`；模板为 `tpl1:<HMAC>`；  
  空值与明文兼容（老数据未加密也不会崩）。
- **密钥指纹**：只报 SHA256 前 16 位，用于审计里核对"换没换密钥"。

### 完整性（防篡改 = 哈希 + 非对称签名）

- **哈希**：**SM3**（无国密库时回退 SHA-256，如实标注，**绝不冒充 SM3**）。
- **非对称签名**：**SM2**（含 SM3 杂凑签名）；无国密库时回退 **RSA-2048 + SHA-256**。
- **签名私钥**：与主密钥同一套保护（DPAPI/Fernet 包裹），落 `keyring/sign.key.enc`，**不明文落盘**；
  公钥 `sign.pub` 可公开（验签只需公钥）。
- **台账**：每条加密记录落库时同步写 `signatures`（record_ref/digest/signature/alg/key_fp）。
- **验签**：`storage.verify_record()` / `verify_all_records()` 用公钥复算，返回被篡改清单。

### 只读不可改（本版核心）

三重纵深防御，任何一层被绕过，下一层仍能发现：

1. **业务层**：`save_candidate()` 已存在即抛 `ReadOnlyViolation`（用 `INSERT` 而非 `REPLACE`）；
   `update_candidate_meta()` 只放行 `legal_hold / legal_hold_reason / consent_id`。
2. **数据库层**：SQLite `BEFORE UPDATE` 触发器按字段比对，改加密载荷直接 `ABORT`。
3. **密码学层**：攻击者卸掉触发器直接 UPDATE 密文，也**改不出对应签名**（无私钥），
   `verify_all_records()` 立刻报出 `bad_count > 0`。

因此**合规的"更正"** = **DELETE(旧) + INSERT(新)**，全程留痕，链路上没有原地修改。

### 安装包加密与防解包（exe 发布）

> 本节记录的是 **exe 打包/加密步骤**，与考生数据的字段级加密是两条独立的链路：
> 前者保护"程序本体不被直接解包"，后者保护"库里的考生数据"。两者都做，才不是只锁门不锁窗。

**构建入口**（在 `exe打包文件` 目录，Git Bash 中执行）：

```bash
cd "exe打包文件"
bash 一键打包.sh
```

打包脚本现在不再把 `payload.zip` 明文追加到 exe，而是按下面的链路生成**加密单文件 exe**：

1. **随机载荷密钥**：构建时生成 32 字节随机密钥 `secret`，只以"逐字节异或 `0x5A`"后的 hex
   通过 `-ldflags "-X main.keyBlob=..."` 注入启动器；构建脚本不落盘明文密钥。
2. **启动器编译**：`go build -trimpath -buildvcs=false -ldflags "-s -w -buildid= -X main.keyBlob=..."`，
   去掉符号表、调试信息、构建 ID 与源码路径。
3. **AES-256-GCM 分块加密**：`加密打包exe文件/encrypt_payload.py` 按 1 MB 分块加密
   `payload.zip`；密钥 = `SHA256(secret + 随机 salt + SHA256(启动器 stub))`。
   每个分块独立 GCM 校验，篡改任意一块都会在安装/启动时立即失败。
4. **尾部索引**：密文后追加 40 字节 `ZKINS002` 尾部（偏移、密文长度、16 字节 salt）；
   启动器先校验文件长度与索引，再派生密钥解密。
5. **安装密码**：首次启动要求输入安装密码 **`123456`**；口令用
   `PBKDF2-HMAC-SHA256(120000 轮, salt="EDY_POWERQ-2026-install", 32 字节)` 校验，
   通过后写 `%LOCALAPPDATA%\智能考场AI巡考系统\.install_auth`（`v4` 格式，HMAC 签名，隐藏文件），
   后续启动不再重复输入。旧版 `v3` 认证文件会被忽略，强制重新输入新密码。
6. **防调试/防动态分析**：启动器在启动时与解包前各做一次检查：
   `IsDebuggerPresent` 与 `CheckRemoteDebuggerPresent`；命中则直接退出，不进入密码框。
   （刻意不扫描 `tasklist`、不调用 `ntdll`，避免被安全软件按“黑客工具”误杀。）
7. **源码硬化**：首次解包后 `_harden.py` 把业务 `.py` 编译成 `.pyc`（`optimize=2`），
   用每目录随机 32 字节 `.zk_key` 异或加密字节码，再把 `.py` 替换为极小的内存加载器；
   安装目录设置为隐藏+系统属性。`runtime/` 标准库不做处理。
8. **完整性**：启动器密钥绑定自身 stub 的 SHA256；修改启动器或密文都会导致
   GCM 校验失败。构建结束会打印成品 SHA256，便于分发核对。

**改安装密码**（例如从 `123456` 换成别的）：

```bash
python -c "import hashlib; print(hashlib.pbkdf2_hmac('sha256', b'新密码', b'EDY_POWERQ-2026-install', 120000, 32).hex())"
```

把输出的 64 位 hex 替换 `exe打包文件/_build/launcher/main.go` 里的 `installHash`，
再执行 `bash 一键打包.sh` 重新编译即可。

**如实说明安全边界**：

- 这套措施能挡住"直接解压 exe 拿源码""用常见反编译器打开 pyc""简单附加调试器"，
  但**不是不可破解的 DRM**。安装后的 `app` 目录仍需本机可读才能运行；
  有管理员权限且具备逆向能力的人，理论上仍可还原内存中的代码。
- 真正需要强保护的场景，应叠加代码签名、授权服务器、原生编译（Nuitka/Cython）
  或商业加壳，并配合法律与合同约束；不要把"加密"宣传成绝对安全。
- 安装密码 `123456` 是**现场演示口令**，正式比赛/交付前应改成强口令并重新打包。

## 九、常见问题

**Q1：报告里显示"无可用加密后端"？**  
安装任一后端即可：`python -m pip install gmssl cryptography`  
（国密优先，故建议装 `gmssl`；装不上时 `cryptography` 回退同样满足要求）。

**Q2：换台电脑（或换了 Windows 账户）后，界面/报告里敏感字段全部解不开？**  
属**预期行为，且不可逆**。主密钥与签名私钥由 **Windows DPAPI** 包裹，
只认生成它们的那台机器 + 那个 Windows 用户；换机后文件还在，但本机没有对应的
DPAPI 主密钥，密文永远解不开（错误码 `0x8009000B`，界面会直接弹中文提示）。
处置只有两条：

1. 回到当初生成密钥的机器/账户上运行；
2. 重置密钥环（**会先整目录备份**，旧文件不会丢，只是解不开）：

```bat
python cli.py keyring                             :: 先体检：每个密钥文件能否解开
python cli.py keyring --reset --yes --with-demo   :: 备份后重建密钥 + 重灌演示数据
```

或双击 **「修复密钥环.bat」**（会先让你输入 YES 确认）。

**Q3：水印为什么没落到图上？**  
本机未安装 Pillow。程序**不会假装打过水印**，会返回水印文本并标注"未落图"。  
安装 `Pillow` 后即真正平铺水印。

**Q4：演示数据会不会冒充真实接入？**  
不会。演示记录统一带 `demo` 标记，报告里单独说明：  
`dpp/demo_flags.py` 定义标记，`demo_data.describe()` 给出说明。

**Q5：怎么清空重来？**  
推荐双击 **「修复密钥环.bat」**，或 `python cli.py keyring --reset --yes --with-demo`：
它会把 `data\` 整目录备份成同级的 `data_backup_<时间戳>\`，再重建密钥与演示数据。
直接删除 `data\` 整个目录也能清空，但没有备份、且下次启动会重新生成密钥。

## 十、与其它主题的关系

本主题对应《项目树/All/README.md》中的 **P0 主题 05**，与**项目三（合规与数据治理）**  
互为表里：项目三给出法律依据与治理框架，本实现给出**可运行的技术控制与验收证据**。

02（摄像头核查）、03（智能终端操作）中已有各自的字段加密（`data_crypto.py`，Fernet）。  
本主题的存储目录、密钥、库**相互独立**，不修改、不接管它们的代码，  
仅在分类分级目录里登记这些数据类别的口径与保留期。

### 与 00_集成联动

`00_集成联动` 通过 `integration_api.py`（**子进程 + JSON**，与其他专题同一约定）调用本专题，
可直接使用的联动能力：

| 方法 | 作用 |
| --- | --- |
| `protect_candidate(...)` | 受保护登记一名考生（加密 + 签名） |
| `handoff_candidate(...)` | 取「最小必要」核验包（编号/座次/考场，**不含**姓名证件号图像） |
| `redact(text)` | 统一脱敏口径（供 01/03 复用） |
| `check_transport(...)` | 传输合规校验（专网 + 加密） |
| `verify_data_integrity()` | 全量完整性验签（是否被篡改） |
| `readonly_probe()` | 只读探针（试改加密数据，必须被拒） |

命令行等价调用：

```bat
python integration_api.py --op status --args "{}"
python integration_api.py --op readonly_probe --args "{}"
```
