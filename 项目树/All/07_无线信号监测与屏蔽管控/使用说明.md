# 07 无线信号监测与屏蔽管控 · 使用说明

> 所属：项目六 · 智能化装备与考生数据保护 ｜ 专题 07（自主补充）
> 定位：补齐 AI 视频/音频覆盖不到的**频谱盲区**——无线作弊器材（隐形耳机、数传模块、

## 三、界面的 8 个页签

### ① 总览
指标卡片：监测站、24h 扫描、待处置异常、严重异常、屏蔽开启、平均时延、监测覆盖、合规分。
右侧一键动作：载入演示数据、跑回放测试、生成验收报告、打开报告目录、立即 tick、
"载入演示并跑回放"一条龙。下方是最近异常与运行日志。

### ② 频谱监测
- 选监测站 + 选预设信号（2.4G 数传 / UHF 耳机 / 5.8G 图传 / 合法 WiFi / 非法频段 / 纯噪声）
- **扫描一帧**：生成模拟频谱 → 走真实检测链 → 频谱图 + 峰值表 + 自动定位
- **连续监视**：每 2 秒生成一帧噪声（验证不误报）；随时点「扫描一帧」注入信号
- **人工录入峰值**：现场手持侦测仪读数直接入库
- 频谱图画出噪声底、检测门限、峰值标注；扫描历史可点选回看

### ③ 异常与定位
- 异常队列（可只看待处置、按严重度过滤）
- 详情：特征匹配依据、频率/带宽/峰值/信噪比、首帧→发现时延、已见帧数、定位、上报 03 记录
- 右侧平面图：监测站 □、屏蔽器 △、侦测仪 ◇、估计位置 ○±半径
- 按钮：**定位**、**复核：成立/误报/归档**（写审计链）、**上报 03**、**关联 06 安检**、**关联 02 机位**

### ④ 屏蔽管控
- 选屏蔽器，显示状态/频段/功率/定向/审批号
- **开机闸门**逐条列出：设备在线、定向已设、扇区 ≤90°、功率 ≤ 上限、审批有效、在考试窗口内、
  未重复开启；不满足就拒绝并写明原因
- 频段多选、功率、开机理由、演练模式
- 开关记录（时间/设备/动作/频段/功率/来源/操作人/原因）——这就是验收要的"开关时段记录"
- 设备台账：新增/编辑监测站、手持侦测仪、屏蔽器（含坐标 x/y、方位角、扇区）

### ⑤ 考试时间表
- 场次维护（名称/日期/起止/提前开机分钟/考场）
- 当前窗口与剩余时间（未到窗口 / 开考前 / 考试中 / 结束后延时 / 已结束）
- **刷新场次状态**、**开关一致性核对**（提前开、超时未关、非考试时段开、整场漏开、覆盖不完整）

### ⑥ 合规与验收
- 合规体检 18 项（红线/技术/证据），通过/需关注/不通过 + 依据
- 审批/报备与运营商协同登记
- 屏蔽效果实测（考场/频段/屏蔽前后/有效率）与外溢实测（测试点/距离/实测 dBm）
- **生成验收报告**（md + csv），结论分"通过 / 有条件通过（证据待补）/ 不通过"

### ⑦ 联动
- 00/02/03/06 可达性；同机子进程 / 跨机局域网两种模式
- 推送测试告警、关联 06 安检结论、关联 02 机位、推送开关记录到 03（跨机）
- 配置 03 接入地址、令牌、联动沙箱目录
- 联动关联记录（谁、什么时候、关联了哪条）

### ⑧ 设置与审计
- 考点/操作员、开考前窗口、功率上限、外溢限值、检测门限、最小信噪比、
  屏蔽自激抬高、宽带判定、持续帧数
- 开关：必须审批、自动开启、结束自动关闭、异常自动上报 03
- 审计链校验（哈希链，任何改动都会暴露出断裂点）、清理 7 天前扫描帧

## 四、五个环节怎么落地

### 4.1 频谱监测（真设备接入）

启动采集服务：

```bat
启动采集服务.bat
REM 或：python ingest_service.py --host 127.0.0.1 --port 9127
REM 跨机：python ingest_service.py --host 0.0.0.0 --port 9127 --token 你的令牌
```

推一帧（三种 body 任选其一）：

```json
{"station_code":"MON-A",
 "bins":[[2400.0,-101.2],[2400.2,-100.8],[2400.4,-99.9]]}
```

```json
{"station_code":"MON-A","noise_floor_dbm":-100,
 "peaks":[{"freq_mhz":2442.0,"power_dbm":-62.0,"bandwidth_mhz":2.0}]}
```

```json
{"station_code":"MON-A","freq_mhz":433.5,"power_dbm":-78.0,"bandwidth_mhz":0.025}
```

```bash
curl -X POST http://127.0.0.1:9127/api/scan ^
  -H "Content-Type: application/json" ^
  -H "X-RF-Token: 你的令牌" ^
  -d "{\"station_code\":\"MON-A\",\"bins\":[[2400,-101],[2402,-100]]}"
```

服务端处理链：

```
归一化 -> 噪声底（中位数+MAD）-> 峰值检测（门限=噪声底+6dB）
      -> 占空推断（窗口内出现比例）-> 特征库匹配（频率45%+带宽30%+占空25%）
      -> 合法特征：只记台账；作弊特征：告警；未匹配：关注/宽带/非法频段
      -> 屏蔽开启时先剔除自身压制信号（否则一开屏蔽就自激误报）
      -> 同站同频合并（±0.6MHz / 180s），持续多帧升级
```

- `source=real` 由采集服务强制标注；模拟器为 `sim`；手工录入为 `manual`
- 安全：默认只监听回环；跨机必须有令牌；非回环又无令牌时**拒绝启动**；
  可选 TCP 行协议（`--tcp-port`）只允许回环监听（TCP 没有请求头放令牌，
  跨机采集一律走 HTTP + `X-RF-Token`）

### 4.2 作弊信号特征库

14 条内置特征：2.4G 数传/跳频、5.8G 图传、UHF/VHF 隐形耳机、GSM/LTE 数传；
合法特征：WiFi 2.4G/5G、蓝牙、考务对讲、运营商基站（GSM/LTE/NR 下行）。

匹配打分可解释：`频率命中 45% + 带宽相似 30% + 占空特征 25%`，再乘特征基准置信度。
带宽相似用**相对差**（2 MHz 与 20 MHz 不会因为 log 比只有 3 倍就被当成相似）。
界面的「本帧峰值」会显示每个峰是"合法（不告警）/ 作弊可疑 / 未匹配"。

### 4.3 信号定位

设备台账里登记监测站坐标（米）后，定位自动选手段：

| 数据条件 | 方法 | 可信度 |
| --- | --- | --- |
| ≥2 个站有测向方位角 | 多站测向交会（两两交点取中位数） | 高（散布越小越高） |
| ≥3 个站有场强 | 对数距离模型 + 加权最小二乘 + 高斯-牛顿 | 中高（残差越小越高） |
| 2 个站有场强 | 加权质心 | 低（建议手持逼近） |
| 1 个站 | 以站为圆心、半径 d 的圆 | 很低（如实标注） |

场强模型：`RSSI = -40 - 10×3.0×log10(d)`（1 米参考 -40 dBm，室内路径损耗指数 3.0）。
现场可用实测标定覆盖 `locate.RSSI_REF_DBM / PATH_LOSS_N`。

手持侦测仪：`locate.probe_hint(prev, now)` 给出"靠近/远离/持平"提示（±3 dB 阈值）。

### 4.4 屏蔽管控

开启前逐条过闸（任何一条不满足都拒绝，并写明原因）：

1. 设备在线、非故障机
2. 定向天线方位角已设置，扇区 ≤ 90°（避免全向外溢）
3. 功率 ≤ 上限（默认 5 W，低功率贴近考场）
4. 有**当天有效**的设台审批/报备，且频段覆盖计划（红线）
5. 此刻在考试窗口内（开考前 15 分钟 ~ 结束 + post_close）
6. 未处于重复开启状态

开启后：写 `jammers_state` + `switch_logs`（人/时间/频段/功率/依据批文/来源），审计链留痕。
时间表 tick 到窗口外自动关闭；审批失效也自动关闭；**设备离线导致关不掉时不假装已关**——
状态保持开启并报警，一致性核对会把它判成"超时未关"，逼现场处置。

功率/定向/外溢：`spill_estimate` 用自由空间路径损耗做**部署前预判**；
验收以外溢实测（`spill_test`）和屏蔽效果实测（`shield_test`）为准，估算值绝不当作验收结论。

### 4.5 考试时间表

- 窗口 = `[开考前 pre_open, 结束 + post_close]`，默认 15 分钟前可开、结束当刻必须关
- 场次状态：未开始 / 进行中 / 已结束（planned / active / closed）
- 一致性核对逐条检查：非考试时段开启、提前开启、超时未关、整场漏开、覆盖不完整、
  开关记录本身异常（重复开启/关闭无开启）
- 容差 30 秒（给设备指令执行延迟），可在 `config.SWITCH_GRACE_SEC` 调整

## 五、合规红线（本模块把每一条做成了可执行检查）

| 红线 | 代码里的落点 | 检查项 |
| --- | --- | --- |
| 依法报备，不得擅自设台 | `shield.evaluate` 的审批闸门 + `store.valid_approval` | `approval` / `approval_doc` / `approval_bands` |
| 定向、低功率、避免外溢 | 方位角必填、扇区 ≤90°、功率上限、外溢估算 | `direction` / `power` / `spill` |
| 仅考试时段开启，结束即关 | `schedule.find_window` + `shield.tick` 自动关闭 | `switch_consistency` / `auto_off` |
| 与运营商协同 | 协同记录（kind=coordination） | `coordination` |
| 不得干扰合法公众通信 | 外溢实测限值（默认 ≤ -85 dBm） | `spill` |

**提醒**：本模块不替代无线电管理机构的审批；"审批编号/批文"必须由考点真实登记，
否则屏蔽器一律开不了（这是故意的）。

## 六、与其它专题联动（只调用，不改其它模块）

```
07 异常 ──SIGNAL_ABNORMAL(红/橙)──> 03 智能终端（分级/去重/复核留痕）
07 设备异常/合规问题 ──OFFLINE(橙)──> 03
06 安检检出无线耳机/手机 ──待处置报警──> 07 关联（同考场重点关注）
02 机位台账/画质 ──credibility──> 07 定位后复核参考（不参与频谱告警分级）
07 开关记录/告警摘要 ──POST /api/records──> 03（跨机部署时驾驶舱"远端设备"可见）
```

- **同机**：走 `00_集成联动/linkage.py` 的"子进程 + 单行 JSON"，并支持沙箱重定向
  （`EXAM_TERMINAL_HOME` / `EXAM_SEC_HOME` / `EXAM_CAMERA_HOME`）
- **跨机**：在「⑦ 联动」填 03 的 `http://IP:9113` 与令牌（`X-Exam-Token`），
  告警走 `POST /api/ingest_alert`，记录走 `POST /api/records`（03 的 `lan_service.py`）
- 03 的告警码只用已登记分级的 `SIGNAL_ABNORMAL`（红）与 `OFFLINE`（橙），
  不往 03 里塞未登记的码；"关注"级会显式下传 `level=orange`，不会把关注级刷成红色
- 为什么 03 网页驾驶舱的"模块态"一栏没有 07：那张表是 03 内置的模块列表，本任务要求
  不改 07 以外的任何文件；07 通过**告警**和**远端记录**进入 03，驾驶舱里能看到 07 的
  告警与设备记录，这是不改 03 前提下的正确做法

联动失败绝不影响主流程：任何跨模块调用异常都会变成 `{"ok": false, "reason": ...}`，
界面如实显示，频谱监测/屏蔽管控继续运行。

## 九、自检与指标

`运行自检.bat` → 375 项，覆盖：配置/存储/特征库/频谱/定位/时间表/屏蔽闸门/回放/
合规/报告/接口/采集服务/界面冒烟/联动沙箱/未污染检查。

回放 8 个场景（模拟数据，source=sim）：

| 场景 | 期望 | 结果 |
| --- | --- | --- |
| S1 2.4G 数传作弊（突发） | 告警 | 检出（数传作弊） |
| S2 UHF 隐形耳机（窄带连续） | 告警 | 检出（隐形耳机） |
| S3 5.8G 无线图传 | 告警 | 检出（数传作弊） |
| S4 合法 WiFi AP | 不告警 | 不误报 |
| S5 纯背景噪声 | 不告警 | 不误报 |
| S6 屏蔽开启后的自身信号 | 必须剔除 | 剔除 6 次 |
| S7 非法频段发射（520 MHz） | 告警 | 检出（非法频段） |
| S8 三站同频 | 告警 + 定位 | 定位 (40.0, 30.0)，误差 0.0 m |

汇总：检出率 100%、误报 0、平均/最大发现时延 1.0 s（目标 ≤10 s）、定位误差 ≤15 m。

**如实说明**：以上是**模拟频谱**上的算法链指标，不代表真实设备的检出率；真实指标要
接上频谱仪/监测站后用现场数据重跑。报告里会写明 `source=sim`，不冒充真实监测。

## 十、限制与注意事项

1. **不发射射频**：本机没有屏蔽器实物，"开启屏蔽"是状态机 + 开关记录；接上真屏蔽器
   后需要在 `shield.turn_on/turn_off` 里加设备指令适配层（协议因厂商而异）。
2. **定位需要坐标/测向**：设备台账没有 x/y 或方位角时，只能给单站径向圆，界面会标低可信度。
3. **外溢以实测为准**：`spill_estimate` 是自由空间估算（无遮挡、正对扇区的最坏情况），
   不能写进验收结论；验收必须用 `spill_test` 的现场实测。
4. **时间表要真实维护**：演示场次按当前时间生成；正式使用请在「⑤ 考试时间表」录入真实
   场次（日期/起止/提前开机），否则自动开关与一致性核对没有意义。
5. **审批是硬闸门**：没有当天有效的设台审批/报备，屏蔽器开不了；演练模式仅用于设备联调，
   记录会标 `drill`。
6. **03 的确认/复核**：03 的接入服务只开放告警接入，跨机复核请在其终端界面完成；
   同机模式下 07 可用 03 自己的 `AlertHub/Reviewer` 走正规确认与复核（不改 03 代码）。
7. **上级 README 未改**：按任务约束只改本目录，`项目树\All\README.md` 里"07 仅方案"
   的表述尚未同步；以本目录的实现与自检为准。

## 十一、常见问题

**Q：点「开启屏蔽」被拒绝？**
看「④ 屏蔽管控」的闸门列表，通常是没有审批、不在考试窗口、没设方位角、扇区 >90°、
设备离线。按提示补齐即可；演练联调可勾"演练模式"（仅记录为 drill，不当作正式开机）。

**Q：屏蔽开着的时候频谱一片"宽带异常"？**
本模块会把屏蔽带内的低信噪比信号识别为自身信号并剔除（S6 场景）。如果仍告警，说明
信号强度明显超过压制噪声（可能定向/绕射），此时确实值得现场复核。

**Q：报告结论"有条件通过"？**
表示没有不通过项，但有证据待补（审批文件、外溢实测、屏蔽效果实测、时间表等）。
报告最后一节「待补证据清单」会逐条列出。

**Q：怎么证明没有污染其它模块？**
跑 `python 工具_检查其它模块是否被污染.py`（只读）：自检刚跑完时 03 的"来自 07 的告警"应为 0；
06/02 真实库不应有 07 的写入。生产运行时 03 里出现 07 告警是正常联动。

**Q：能只跑命令行不装界面吗？**
可以。全部能力都在 `integration_api.py` / `演示.py` / `自检.py` 里，界面只是壳。
Python 3.10+ 即可，无需 pip 安装任何包。
