智能终端操作端 · 程序结构
============================================================
对应《智能终端.md》。本目录是终端侧软件实现。

【入口】
  启动终端界面.bat      -> terminal_gui.py（桌面界面，4 页签）
  运行自检与测试.bat    -> 单元测试(124) + 端到端自检(74)
  main.py               -> 端到端自检；默认用临时数据目录，--real 用真实目录
  terminal_gui.py       -> 界面；登录后按角色装配视图

【模块与职责】
  config.py    路径解析(DATA_ROOT)、终端类型、告警分级元数据(LEVEL_META)、
               角色动作矩阵(ROLE_ACTIONS)、断网与管控阈值、时钟与播报表、AI 检测设置(load_ai_settings/save_ai_settings)
  models.py    Alert（含分级/SLA/脱敏展示/序列化）、ReviewRecord、
               canonical()、chain_hash() 哈希链原语
  storage.py   SQLite：alerts / reviews / audit(哈希链) / commands / kv
               提供 verify_chain() 篡改检测、false_positive_stats() 误报闭环统计
  access.py    终端账户(PBKDF2 加盐)、Session、can()/require()、
               room_filter() 考场隔离、visible_alerts()、render() 脱敏、
               export_payload()（受 export 动作限制）
  alerts.py    AlertHub：ingest(分级兜底+去重) / ack(红色强制确认) /
               display_order(红优先-超时次之) / fetch_from_edge(断网不抛异常) /
               simulate(演示数据，source=demo 不冒充真实接入)
  review.py    Reviewer：review(结论必填+理由必填+附件留档) /
               report(一键上报，受考场范围限制) / stats / timeline 全过程留痕
  offline.py   ConnectivityProbe(可注入) + Outbox：enqueue 落 SQLite + NDJSON、
               flush 批量补传、失败保留下次再传、超期标记不静默丢弃
  fleet.py     FleetManager：配置快照(外设浅合并)、应用白名单核查、
               外设策略、远程擦除(二次确认码 WIPE)、升级任务登记、
               apply_pending 指令生效、soak_tick/soak_status 稳定性取证
  clock.py     StandardClock：standard_time(来源如实标注)、drift 偏差、
               check_and_alert 产生 CLOCK_DRIFT 告警、广播时刻表与到点触发留痕
  bridge.py    FaceBridge(隔离子进程调 01) + PlatformLink(平台/边缘/认证 HTTP，
               未配置即如实报"未配置") + CmdBridge(隔离子进程调 01 的命令控制台：
               本端开关快速拦截 + role 原样传给 01 + 每次调用写审计链)
  _face_bridge.py  子进程侧：把 01 目录放进 sys.path，调用其 verifier，
               以最后一行 JSON 回传；异常一律 ok=false 不伪装成功

  console.py   命令控制台开关与层级（默认**全部关闭**，标记文件语义）：
               console_enabled/set_console(总开关 data\cmd_console.on)、
               console_admin_allowed/set_console_admin(管理员授权
               data\cmd_console_admin.on)、console_tier(role) 唯一判定入口
               （owner=full / admin且授权=ollama / 其它=none；总开关关=一律 none）、
               bridge_home() 把开关镜像给 01 侧数据根（不写 01 目录）
  _cmd_bridge.py   子进程侧：把 01 目录放进 sys.path，调用其 cmd_console.execute，
               **不自行判权限**（role 原样传，由 01 的 accounts.cmd_console_tier 定），
               以最后一行 JSON 回传；设 sys.dont_write_bytecode 保证对 01 只读

  person_detect.py  【AI 框选识别，与 02 逐字节相同，2026-10-14 已整体替换为
               「YOLO11n ONNX 版」（1,611 行 / 70,810 字节）】
               检测链按固定优先级自动选择（界面/配置**无法**指定后端族）：
               YOLO11n ONNX(主力；models\yolo11n.onnx，可用环境变量
               EXAM_YOLO_MODEL 覆盖；输入固定 640×640，只解码 COCO person 类)
               > MobileNet-SSD(仅当本目录存在 MobileNetSSD_deploy.prototxt
               + .caffemodel 时启用) > HOG+SVM(兜底)；
               YOLO 可用时某帧零检出仍会叠加一次 HOG 兜底并合并；
               【密集考场 40 人】分块（切片）推理（yolo_tiling=auto/on/off）：
               分析帧长边 ≥ 640×1.35 时切成 yolo_tile_size(640) 的块，每块按原生像素
               送模型（等效放大 长边÷块边 倍），跨块去重并优先保留未被切断的框；
               贴脸大目标（高度≥45% 或面积≥12%）时自动回落单张推理；单帧最多 12 块；
               人多(>12) 时只给异常/越界框写文字；
  工具_密集场景评测.py 40 人考场评测（与 02 同一份）：真实裁片合成 8×5 场景，
               对比 分析长边/分块/块大小/置信度/去重阈值 的召回-精确-耗时；
               实测 640 单张 12.5% → 1280 单张 22.5% → 1280+分块 62.5%
               EXAM_YOLO_DISABLE=1 强制禁用 YOLO、EXAM_YOLO_EP=coreml 优先 CoreML；
               依赖 onnxruntime，缺失即静默回落 HOG（不报错、不崩）；
               行为判定用框几何 + Haar 人脸/人眼辅助（无姿态/骨架环节）；
               去重：IoU-NMS + "部分-整体"两级去重（_suppress_contained/_iomin，
               小框被大框包住且中心在框内才丢，阈值 0.85）；
               辅助源（背景差分 / Haar 人头）只在主链零检出时兜底，避免一人多个框；
               逐人信息字段 pid/rect/action/bad/crosses/behaviors/density_level；
               后端如实判定：YOLO 会话已建=YOLO11n-ONNX，否则 MobileNet-SSD，
               都没有=HOG+SVM（terminal_gui 显示在状态栏并写 data\ai_backend.txt）
  工具_模型对比.py  检测链可用性自检(--selftest，打印"检测链") + 同一素材上
               YOLO11n-ONNX 行 vs HOG+SVM 行的速度/人数波动/轨迹连续性/精度对比
               （MobileNet-SSD 缺模型时如实标"未参与"）；--input-dim 默认 640；
               报告落 data\reports\
  工具_YOLO模型导出.py  从 yolo11n.pt 导出 models\yolo11n.onnx（一次性依赖
               pip install ultralytics onnxslim；改 MODEL_NAME 可换 yolo11s）
  下载模型.py   只提供 yolo11n.onnx / yolo11s.onnx 两个检测模型（姿态类参数已删除）；
               从 ultralytics 官方 release 下载并校验 SHA256；本地导出件哈希与官方 release 不同属正常
  cheat_bridge.py 【作弊识别结合层，2026-10-14 新增，与 02 逐字节相同】
               逐人检测结果 → FrameFeatures → cheatdetect 时序引擎（风险分数 + 窗口 2s +
               持续超阈 1s 才告警，单帧瞬时动作被抑制）；本终端状态栏显示风险等级、
               告警写监控日志并上报。引擎本体在 作弊识别\（与 02/00 同一份）。
  vlm_detect.py 【多模态大模型（VLM）检测引擎，本版新增，与 02 逐字节相同】
               VlmPersonTracker 继承 person_detect.PersonTracker，只替换检测源 _detect()：
               多模态为主（后台线程按间隔刷新，结果新鲜用它的人框/行为/可疑物品），
               超时/报错/结果过期则本帧回落 YOLO11n（跟踪/编号/画框/越界/告警复用原链路）；
               后端可切换：ollama（/api/chat + images；/api/tags、/api/show 探测 capabilities）
               与 api（OpenAI 兼容 /chat/completions + image_url data URI，Bearer 鉴权）；
               输出强制 JSON（persons/objects/summary），坐标 0~1000 相对，行为词走 ACTION_ALIASES；
               provider=off 时与旧版完全一致
  工具_多模态检测.py --check / --pull / --image / --write-settings / --prompt；
               与 02 同一份工具（设置文件路径各项目自己解析）
  多模态检测.bat  菜单式启动器（choice 菜单，支持"多模态检测.bat check"参数式）

【数据流】
  边缘/平台 --HTTP--> AlertHub.ingest --> SQLite(alerts) --+
                                    \--> Outbox(synced=0) --恢复--> 平台 POST /alerts
  处置:  红色 -> ack(强制) -> review(理由+附件) -> 误报闭环统计
  管控:  平台 commands -> fleet.apply_pending -> 配置/外设/擦除(二次确认)/升级登记
  时钟:  授时 -> drift -> 超限产生告警；时刻表到点 -> 播报 + 审计
  核验:  界面 -> FaceBridge -> 子进程 _face_bridge -> 01 模块 -> JSON 结果
  控制台: 界面 -> CmdBridge(console_tier 快速拦截) -> 子进程 _cmd_bridge
          -> 01 cmd_console.execute --(accounts.cmd_console_tier 最终判定)--> 执行
          -> 本端审计链(每次调用，含被拒) + 01 审计链(落在 data\cmd_bridge_home)
  权限分层: 默认关闭；owner=完整 cmd/python；admin=仅在"总开关开 + 单独授权"时
          可用 `ollama run <模型> [提示词]`（白名单复用 01 的 parse_ollama_command，
          03 端不复制、不放宽）；其它角色 none

【对外接口（平台侧需实现）】
  GET  /health     联通性探测
  GET  /time       平台授时 {"epoch": ...}
  GET  /alerts     告警订阅 {"alerts":[...]}
  POST /alerts     终端补传告警
  GET  /commands   平台指令 set_config/peripheral/wipe/upgrade/report

【不在本目录范围（采购/部署事项）】
  国产化 OS 与信创整机、国密算法、MDM 服务端、终端准入与设备指纹、
  防拆开关、多路视频解码、签到抽签业务
