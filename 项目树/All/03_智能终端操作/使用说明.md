# 使用说明 · 智能终端操作端

> 对应《[智能终端.md](智能终端.md)》。
> 本目录是**终端侧软件的真实实现**（可运行、有测试）；硬件选型与 MDM 服务端属采购范围。

## 一、怎么启动

| 想做什么 | 双击 |
| --- | --- |
| 打开终端界面 | **启动终端界面.bat** |
| 一键体检（单元测试 + 端到端自检） | **运行自检与测试.bat** |

命令行方式：

```bat
python terminal_gui.py                 :: 打开界面
python -m unittest discover -s tests -t .   :: 230 项单元测试
python main.py                         :: 74 项自检（用临时数据目录，不污染真实数据）
python main.py --real                  :: 用真实 data 目录自检
```

## 三、界面页签怎么用

> 页签数量随角色权限变化（所有者可见「命令台 / 数据维护 / 监控查看」等），
> 下面是完整版；看不到的页签说明当前角色没有该权限，不是故障。

### 1. 告警处置
- 列表按 **红色优先、其次超时、再按时间** 排序；红色底红字、橙色底黄字
- **红色预警**会弹窗提醒，且**必须先点「✓ 确认选中」才能复核**
- 考生编号**默认脱敏**（`3301**********1234`）
- 选中一行，下方会显示该告警的**全过程留痕**（接入 → 确认 → 复核）
- 巡考员/指挥中心可点「🧪 生成演示告警」造一批橙色+红色数据（来源标注 `demo`，不冒充真实接入）
- 右上「☁ 立即补传」把待补传告警推给平台

### 2. 复核留痕
- 填 **告警 ID**（在告警页选一行会自动带入）、**结论**（成立/不成立/误报）、**见证人**、**附件**、**理由**
- **理由必填**——留痕要求，不填提交不了
- 结论选「误报」会自动进入**算法迭代闭环**，可在「误报统计」里按告警码看误报率
- 附件支持 `.png/.jpg/.jpeg/.webp/.txt/.pdf/.mp4`，会拷进 `data\attachments\` 留档

### 3. 手持核验
- 调 **01_人脸识别与身份核对** 做真实人脸核验（子进程隔离调用，不复制算法）
- 选模式（1:1 / 1:N）、填考生编号、选图片 → 开始核验
- 顶部会如实显示桥接状态：01 目录、`verifier.py`、人脸模型三者缺一就会提示缺什么
- **未建档时不会假装成功**，会明确提示"特征索引不可用（需先建档）"

### 4. 运行状态与管控
- 左侧：在线状态、待补传条数、告警统计、**审计链校验**
- 右侧：统一管控配置（白名单/外设）、**稳定性心跳与最长连续时长**、标准时间与下一条播报
- 「写一次稳定性心跳」手动写一条；界面运行时每 30 秒自动写
- 最下面一行是**命令控制台**（默认关闭）：所有者看到「命令控制台」复选框 +
  「允许管理员使用 AI 辅助判断（仅 ollama）」复选框；有权限时才出现「⌨ 命令控制台」按钮

### 5. 监控查看（多摄像头 + AI 逐人框选）

**（1）画面大小 / 每行几路**
- 顶部第二行有「画面大小：小 / 中 / 大 / 超大」和「每行：1 / 2 / 3 / 4」；
  选择会立即生效并记住（`data\monitor_ui.json`），下次打开还是这个布局。
- 只有 1 路时自动占满一行并居中；多路时按「每行几路」均分宽度，面板会按窗口
  实际宽度等比收窄（保持 16:9），不会横向溢出。
- 默认「大」= 640×360；「超大」= 800×450。窗口高度不够时用右侧滚动条往下看。

**（2）点一下画面就放大（本次新增）**
- **单击任意摄像头画面**（或点面板里的「🔍 放大」）弹出独立放大窗口：
  左侧大画面 + 右侧实时信息（人数 / 越界 / 密度 / 分析长边 / 检测链 / 人员列表）。
- 放大窗口里**再点一下画面 = 全屏**；`F11` 切换全屏；`Esc` 先退全屏、再按一次关闭。
- 放大窗口里的「⏹ 停止 / ▶ 播放」控制的就是这一路，关掉窗口不会停止取流。
- 同一路只会开一个放大窗口，重复点击是把已开的窗口提到最前。

**（3）AI 显示怎么读**
- 边框：**绿=正常，橙=有异常行为，红=越界**；顶部状态条汇总
  `播放 X/Y 路 ｜ AI 总人数 N ｜ 越界 M ｜ 异常行为 K ｜ 高密度机位 J 路`。
- 右上角如实显示 `AI识别中：N 人，越界 M ｜ 后端：YOLO11n-ONNX（分块 N）`。
- 勾掉「AI 辅助识别」只停 AI，不影响看画面；该开关仅所有者可调。
- 所有者可用「🎯 YOLO 识别设置」调检测模式/分析长边/置信度/分块方式，保存即生效
  （检测器重建，正在播放的流不中断），详见第八节。

## 四、断网怎么表现

1. 告警接入后**先落本地**（SQLite `synced=0` + `data\outbox\outbox.ndjson` 备份），本机功能完全不受影响
2. 状态栏显示"离线"，待补传条数照常累加
3. 网络恢复后**自动批量补传**（也可手动点「☁ 立即补传」），成功才置为已同步
4. 超过 72 小时的陈旧记录**不静默丢弃**，标记后写一条「补传超期丢弃」审计

## 六之二、接另一台设备（局域网联动）

**场景**：一台设备跑 01 人脸识别 / 02 摄像头核查，另一台设备跑本终端（03），
两台在同一个局域网 —— 前者的操作记录、核验记录、核查结论、整改工单、告警都要到终端来。

**本终端侧（设备 B）**

```bat
:: 双击也行；跨设备时监听地址填 0.0.0.0（默认只监听本机 127.0.0.1）
启动局域网接入服务.bat
```

  `python lan_service.py --print-token` 可随时查看。
- **默认只监听本机**。要跨设备必须显式监听 `0.0.0.0`，且必须已有令牌，否则服务拒绝启动。
- 防火墙：跨设备时需放行该端口（首次运行 Windows 会弹窗询问）。

- 收下来的远端记录不在界面上，用命令查看：

```bat

python integration_api.py --op list_remote --args "{\"device_id\":\"PC-A-01\",\"kind\":\"verify\"}"
```

**对端（设备 A）**：在 01 / 02 各自目录里双击 `上报到智能终端.bat`，

## 七、注意事项

1. **远程擦除需二次确认**：`execute_wipe()` 必须传确认码 `WIPE` 才执行；执行时如果数据库正被占用，
   会**如实报告哪一项没删掉**，不会谎报成功。
2. **升级只登记不刷机**：`upgrade` 指令只记录任务与校验信息，实际刷机不在本模块。
3. **稳定性未满 72 小时就是"未达标"**：`soak_status()` 按心跳间隔判定连续性，缺口会断掉连续时长。
   这项验收**必须靠真实运行积累**，代码只能帮取证。
4. **脱敏是默认行为**：导出也走脱敏口径（`access.export_payload`）。
5. **审计链**：所有接入/确认/复核/管控动作都进 `sha256(prev + 规范化JSON)` 哈希链，
   可在界面点「校验审计链」验证是否被篡改。
6. **本目录不做视频解码**，也不落地全量视频——符合《智能终端.md》第四节"终端不落地全量视频"的约束。

## 八、AI 框选识别与检测模型（可选，不配也能跑）

监控页的「AI 辅助识别」勾选框背后是 `person_detect.py`；它与 **02/11 项目逐字节相同**
（2026-10-19 版：1,592 行 / 84,825 字节；2026-10-14 已整体替换为**「YOLO11n ONNX 版」**）。
检测链**固定按优先级自动选择，界面与配置都无法指定后端族**：

| 优先级 | 检测链 | 需要的文件 |
| --- | --- | --- |
| 1 | **YOLO11n ONNX（主力）** | `models\yolo11n.onnx`（可用环境变量 `EXAM_YOLO_MODEL` 覆盖）；输入固定 640×640，只解码 COCO **person** 类 |
| 2 | MobileNet-SSD（兼容保留） | 本目录存在 `MobileNetSSD_deploy.prototxt` + `.caffemodel` 时启用 |
| 3 | HOG+SVM（内置兜底） | 无需文件，OpenCV 自带 |

- YOLO 可用时，**某帧零检出才会补跑 HOG 兜底**；且为避免"空画面每帧跑 HOG 把界面卡住"
  （HOG 单次约 1 秒），YOLO 就绪时最多每 `hog_fallback_sec`（默认 2 秒）补一次；
  纯 HOG 模式仍每帧都跑。
- `EXAM_YOLO_DISABLE=1` 强制禁用 YOLO；`EXAM_YOLO_EP=coreml` 优先 CoreML（不可用自动回退 CPU）。
- 依赖 `onnxruntime`，**缺失即静默回落 HOG**（不报错、不崩）。
- 行为判定用**框几何 + Haar 人脸/人眼辅助**；当前检测链里没有姿态/骨架环节。
  `闭眼/趴睡` 是 Haar"有脸但找不到眼睛"的近似判断，低头看屏幕时可能误报，只作弱提示。
- 同一个人被检成"头/上半身 + 整体"时会**自动去重**（只留整体框）；Haar 人头与背景差分
  改成**只在主链零检出时兜底**，所以单人画面不会画出一堆框。
- 取流偶尔会吐出一帧 HEVC 灰块/花屏：界面会**跳过该帧、保留上一帧好画面**，
  不把坏帧送进 YOLO（否则会生成莫名框、污染轨迹与告警）。

**模型放哪里**：默认位置就是本目录的 `models\yolo11n.onnx`（**已随目录分发**，
10,741,326 字节；同目录另有导出源 `models\yolo11n.pt`，5,613,764 字节）。
想换别的模型有两种办法：设环境变量 `EXAM_YOLO_MODEL`，或在设置里填 `yolo_model_path`；
**不需要改代码**。

**怎么确认当前用的哪个后端**：监控页状态栏会显示
`AI识别中：N 人，越界 M　｜　后端：YOLO11n-ONNX`；同时会写到
`data\ai_backend.txt`，可直接查看。判定依据是**真实的检测链**（YOLO 会话已建 =
`YOLO11n-ONNX`；否则 MobileNet-SSD；都没有 = `HOG+SVM`）。
**没放模型时会明确显示 HOG+SVM，不会让你误以为在用 YOLO。**

**可选设置** `data\ai_settings.json`（不放就是默认值，与 02 同一套格式）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `ai_mode` | `auto` | `auto`=按路数自动（1 路 1920 / 2~4 路 960 / 更多 640）；`standard`=640；`dense`=1280+分块；`energy`=416 |
| `ai_input_dim` | `0` | 直接指定分析长边；`0`=按 `ai_mode` 取预设（手动填会覆盖 auto） |
| `yolo_model_path` | 空 | 显式指定 YOLO onnx（留空=自动用 `models\yolo11n.onnx`） |
| `yolo_conf` | `0.25` | YOLO 置信度阈值（漏检多降到 0.20，误检多升到 0.30~0.35） |
| `yolo_iou` | `0.45` | YOLO 后处理 NMS 的 IoU 阈值 |
| `yolo_input_dim` | `640` | YOLO 输入边长（官方导出固定 640，一般不用改） |
| `yolo_tiling` | `auto` | `auto`（分析长边 ≥ 864 自动分块）/ `on` / `off` |
| `yolo_tile_size` | `640` | 分块边长（与模型输入一致；480 更细更慢） |
| `yolo_tile_max` | `12` | 单帧最多几块（限制算力上限） |
| `yolo_tile_margin` | `0.0` | 块外扩比例；现场发现块边界的人框总不全时可试 0.05~0.08 |
| `hog_fallback_sec` | `2.0` | YOLO 就绪时，空画面补跑 HOG 的最小间隔（秒） |
| `detect_backend` | 空 | **只读展示位**，由终端按实际检测链回填 |

构造参数按 `person_detect.PersonTracker` 的**真实签名过滤**，参数换代不会把识别链打挂；
旧版那些"指定后端族 / 走独显 / 绘制骨架"的设置键已随 2026-10-14 模型层替换删除。

**算法实测调优（2026-10，已落进代码；以下为 HOG 兜底模式的实测）**：HOG 的密集网格在
416~640 这类小图上**耗时涨 5 倍而检出反而更少**（416：45.9ms/4 人 → 7.3ms/5 人），
因此改为**按送检尺寸自适应**（≥1000px 才启用）；分析长边由 416 提到 **640**
（HOG 窗口要 128px 高，416 下"坐着的人"只有约 70px，必然漏检）。生产路径实测
**54.9ms → 16.1ms，提速 3.4 倍**，9 路单核占用 99% → 29%。算力紧张用 `energy`(416)，
密集考场用 `dense`(768)。HOG 检不全密集考场是算法上限，**而这条兜底路现在只在没有模型时
才会走**——主力已换成 YOLO11n ONNX（`models\yolo11n.onnx`）。

**本机实测（2026-10-14，可直接引用）**：

```bat
python 工具_模型对比.py --selftest          :: 检测链：YOLO11n 就绪(yolo11n.onnx)；MobileNet-SSD 缺模型；HOG+SVM 兜底可用
python -m unittest discover -s tests -t .   :: Ran 325 tests, OK（2026-10-19 实测）
python ui_selfcheck.py                      :: UI 启动自检通过（含放大窗口/识别设置/画面布局）
```

**对比实验（写报告/答辩用）**：`工具_模型对比.py` 对比的是
**YOLO11n-ONNX 行 vs HOG+SVM 行**（MobileNet-SSD 缺模型时如实标"未参与"），
`--input-dim` 默认 **640**，报告落 `data\reports\`：

```bat
python 工具_模型对比.py --selftest                        :: 检测链可用性自检（打印"检测链"）
python 工具_模型对比.py --video data\xxx.mp4 --frames 120  :: 真实录像上比 YOLO11n-ONNX / HOG+SVM
```

**手机识别（考试违规使用手机）——该能力已下线**：当前检测链只解码 COCO 的 **person**
类，**不做手机识别**，也不会再产生手机告警。需要该能力请接入
`06_智能安检与手机作弊器材检测`。

> **历史实测记录（旧引擎时期，检测链含 cell phone 类；该能力已随 2026-10-14
> 模型层替换下线）**：`yolo11n` 的 cell phone 类对"考场里学生手上的手机"基本无响应
> ——确知有手机的真实照片上，手机类峰值只有 0.0001~0.0007，且与输入分辨率无关。
> 当时要让这条能力可用需要：① 用考场实拍微调专用模型；② 换更大模型（**存疑，未实测**）；
> ③ 接入 `06_智能安检与手机作弊器材检测`。旧版状态栏曾显示手机类峰值，**现已不再显示**。

**模型获取与导出**：本目录**已附带** `models\yolo11n.onnx`（10,741,326 字节）
与导出源 `models\yolo11n.pt`（5,613,764 字节）。需要重新导出/下载时：

```bat
python 工具_YOLO模型导出.py   :: 从 yolo11n.pt 导出 onnx；一次性依赖 pip install ultralytics onnxslim（可换 yolo11s）
python 下载模型.py --check   :: 检查已有模型
python 下载模型.py           :: 下载官方预导出的 yolo11n.onnx（带 SHA256 校验）
```

`下载模型.py` **只提供 `yolo11n.onnx` / `yolo11s.onnx` 两个检测模型**；
**本地导出的 onnx 与官方 release 哈希不同属正常**。

**关于 GPU（如实说明）**：pip 安装的 `opencv-python` **没有编译 CUDA**，
`cv2.cuda.getCudaEnabledDeviceCount()` 恒为 0，所以 `cv2.dnn` 走不了独显；
YOLO 推理走 `onnxruntime`，默认 `CPUExecutionProvider`，设 `EXAM_YOLO_EP=coreml`
时优先 CoreML（不可用自动回退 CPU）。**独显加速未实测。**

### 多模态大模型（VLM）检测（本机版新增，可选）

本版把检测源换成了**能看图的多模态大模型**：由模型直接判读"谁在干什么、有没有手机小抄"，
YOLO11n 保留为兜底；**不开启时与上一版完全一致**。

| 后端（`vlm_provider`） | 需要填 | 适合 |
| --- | --- | --- |
| `off`（默认） | — | 只用 YOLO11n（等于上一版） |
| `ollama` | `vlm_model`（如 `qwen2.5vl:3b`） | 数据不出本机 |
| `api` | `vlm_model` + `vlm_base_url` + `vlm_api_key` | OpenAI 兼容的云端多模态 |

> ⚠ Ollama 必须用**能看图**的模型。本机当前只有 `Qwen3-4B`（纯文本），
> 它不能看图，多模态会一直如实回落 YOLO11n。先拉一个视觉模型：
> `python 工具_多模态检测.py --pull`（默认 qwen2.5vl:3b，约 3~4GB）。

**配置**（`data\ai_settings.json`，与 02 同一套格式）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `vlm_provider` | `off` | `off` / `ollama` / `api` |
| `vlm_model` | 空 | `qwen2.5vl:3b`（ollama）/ `qwen-vl-max`（api）等 |
| `vlm_base_url` | 空 | 留空=默认（ollama→127.0.0.1:11434） |
| `vlm_api_key` | 空 | 只有 api 需要 |
| `vlm_interval` | 3.0 | **每路每 N 秒最多一次**多模态调用（多模态慢，别小于 2 秒） |
| `vlm_max_dim` | 896 | 送模型的图片长边（调小更快） |
| `vlm_timeout` | 60 | 单次调用超时（秒） |

也可用环境变量临时切换：`EXAM_VLM_PROVIDER` / `EXAM_VLM_MODEL` / `EXAM_VLM_BASE_URL` /
`EXAM_VLM_API_KEY` / `EXAM_VLM_INTERVAL` / `EXAM_VLM_MAX_DIM` / `EXAM_VLM_TIMEOUT`。

**怎么验证**：`python 工具_多模态检测.py --check` 看配置与连通性；
`python 工具_多模态检测.py --image <一张考场图>` 打印模型的 JSON 并把框画出来（落 `data\reports\`）；
双击 `多模态检测.bat` 是同一套功能的菜单。

**状态栏如实显示谁在出框**：`AI识别中：N 人，越界 M　｜　后端：多模态(<模型>)`
（结果新鲜）、`多模态→YOLO11n 兜底`（超时/报错/过期）、`YOLO11n-ONNX` 或 `HOG+SVM`（没开多模态）；
同时写 `data\ai_backend.txt`。**不猜**：模型没返回合法 JSON 或框不合法时按本次失败处理并回落。

### 密集考场 / 多人画面：用「自动」模式（ai_mode=auto，默认）

一个 1080p 机位看 40 个考生时后排只有几十像素高；单张推理会把整帧压到 640，
**把分辨率提到 1280/1920 也救不回来**。因此本版（2026-10-19 起）：

1. **自动档 = 按当前播放路数给分析长边**：1 路 **1920**、2~4 路 **960**、5 路以上 **640**
   （也可手动 `ai_input_dim` 或选 `standard/dense/energy` 固定档）；
2. **分块（切片）推理**：把画面切成 640 的块，每块按原生像素送模型（等效放大 2~3 倍），
   `yolo_tiling=auto` 只在大画面启用；贴脸大目标时自动不分块；
3. **跨块加权框融合（WBF）**：同一个人被相邻两块各检一次时，按置信度加权平均成一个框
   （旧版直接丢一个，框会随块边界抖；切成两半时还会被算成两个人）；
4. **分块推理在后台线程跑**：1920 单次约 300 ms，界面线程只贴缓存框，
   视频/按钮/放大窗口不会被卡住。

实测（`python 工具_密集场景评测.py`，合成 40 人考场，真人裁片）：

| 分析长边 | 召回 | 精确 | 单路分析 |
| --- | --- | --- | --- |
| 640（旧默认） | **17.5%** | 100% | 约 28 ms |
| 960 | **52.5%** | 100% | 约 91 ms |
| 1280 | **62.5%** | 86.2% | 约 217 ms |

真实摄像头画面实测（2960×1666，6~8 人教室，同一帧）：
**960 → 6 人 ｜ 1280 → 4 人（后排/被挡的人漏）｜ 1920 → 8 人（全部找到）**。
这就是 auto 档给单路 1920 的依据。

- 状态栏在分块时显示 `后端：…（分块 N）`，`data\ai_backend.txt` 同步；
- 人多时只给异常/越界框写文字，画面不被糊死；
- 更准更慢：`yolo_tile_size=480`；更大模型：`yolo11s.onnx`；
- **如实说明**：合成场景只用于横向对比，真实考场准确率必须用现场样本。

## 九、命令控制台（默认关闭，高风险）

以 owner 登录后，在「运行状态与管控」页最下面一行：

1. 勾选 **「命令控制台」** → 弹确认框（说明风险：等同本机完全控制权）。**不确认就不会开启**。
2. 需要给管理员用时，再勾选 **「允许管理员使用 AI 辅助判断（仅 ollama）」**；
   总开关关闭时这个复选框是灰的——**授权必须有总开关才生效**。
3. 点 **「⌨ 命令控制台」** 打开执行窗口：

| 你的角色 | 类型可选 | 能执行 |
| --- | --- | --- |
| 所有者 | 系统命令 / Python 代码 | 任意命令与代码 |
| 管理员（已授权） | **只能是 AI 辅助(ollama)**（选择框禁用） | **仅** `ollama run <模型> [提示词]` |
| 其他角色 | 看不到按钮 | 无 |

4. 填超时（默认 60 秒，最长 600 秒）→ 点「▶ 执行」。执行在**后台线程**里跑，
   界面不会卡；输出按纯文本原样显示（stdout / stderr / 退出码 / 耗时 / 是否截断 / 是否超时）。
5. **每一次执行（包括被拒绝的尝试）都写审计链**（本端一条 `命令控制台`，01 侧再写一条哈希链）。
   可在运维页点「校验审计链」验证是否被篡改。

**必须知道的边界**：

- `ollama run` 的白名单由 **01 的 `parse_ollama_command()`** 判定，03 端**没有**复制或放宽规则；
  执行时不走 shell，所以提示词里的 `| > & ;` 只是普通文本。
- 非所有者即使绕过界面直接跑桥接脚本，也会被 01 的 `accounts.cmd_console_tier(role)` 拒掉
  （有单测证明"命令确实没有被执行"，而不只是"返回了失败"）。
- 所有者这一级**没有命令白名单**（任意代码执行与白名单互斥），也不做降权隔离；
  真正的防线是"谁能登录所有者 + 开关是否打开"。**部署前请先改掉默认口令。**
