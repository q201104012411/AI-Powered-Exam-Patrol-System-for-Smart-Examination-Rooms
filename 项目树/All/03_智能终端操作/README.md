### 命令控制台（默认关闭，与项目一同一套权限规则）

> ⚠ 开启后，能打开这个窗口的人即拥有本终端（本机）的完全控制权。这是**任意代码执行**能力，
> 不是"方便工具"；默认关闭、两级授权、每次执行（含被拒绝的尝试）都写审计链。

| 角色 | 层级 | 能执行什么 |
| --- | --- | --- |
| 所有者 owner | `full` | 任意系统命令、Python 代码 |
| 管理员 admin（且被所有者单独授权） | `ollama` | **仅** `ollama run <模型> [提示词]`，用于 AI 辅助判断 |
| 其他角色 | `none` | 无权限 |

- 两把开关都是标记文件：`data\cmd_console.on`（总开关）、`data\cmd_console_admin.on`（管理员授权）；
  **总开关关闭时，即使已授权管理员也一律 none**。
- 权限判定只有一份实现：本端 `console.console_tier()` 做快速拦截，真正的执行与最终层级由
  **01 的 `cmd_console.execute()` + `accounts.cmd_console_tier(role)`** 判定（`_cmd_bridge.py`
  只原样传 `--role`，不自行放行）。管理员那一级的 `ollama` 白名单由 01 的
  `parse_ollama_command()` 保证——**03 端不复制、不放宽**。
- 桥接子进程用 `EXAM_HOME` 把 01 的数据根指到 `data\cmd_bridge_home\`，因此**不往 01 目录写任何文件**，
  01 侧的审计链与临时文件也落在本端数据目录。

## 三之二、局域网联动（03 作为接收端 · 2026-10-15 新增）

**另一台设备上的操作记录能不能上传到本终端？** 能。设备 A 跑 01/02，设备 B 跑 03，
同一局域网时：

```
设备 A（01 人脸识别 / 02 摄像头核查）                     设备 B（03 智能终端）
  push_oplog.py  ──操作日志 + 核验记录哈希链──┐
  push_oplog.py  ──审计 + 核查结论 + 工单────┤ POST http://<B的IP>:9113/api/records
  push_oplog.py --alert 或 联动层 raise_alert ┼ POST http://<B的IP>:9113/api/ingest_alert
                                             └→ lan_service.py ──→ terminal.db
                                                                    ├ remote_records（分链存放）
                                                                    ├ remote_devices（设备台账+链头）
                                                                    └ audit（只写一条接入回执）
```

| 你在这台设备上做 | 命令 / 入口 |
| --- | --- |
| 开启接收（默认只监听本机） | 双击 `启动局域网接入服务.bat`；跨设备时监听地址填 `0.0.0.0` |
| 查看/生成接入令牌 | `python lan_service.py --print-token`（或设 `EXAM_TERMINAL_TOKEN`） |
| 自检接收端 | `python lan_service.py --selfcheck`（临时数据目录 + 临时端口） |
| 端到端自检（00 里） | 双击 `00_集成联动\局域网联动自检.bat`（真起服务、真跑 01/02 客户端，38 项） |

对端（01/02）做的事：双击各自目录下的 `上报到智能终端.bat`，填终端地址与令牌即可
（会记住到 `终端上报配置.bat`）；也可 `python push_oplog.py --loop 120` 常驻上报。

**三条安全约定（都写在代码里，不是口头承诺）**

1. 默认只监听 `127.0.0.1`；跨设备必须显式 `EXAM_TERMINAL_LAN_HOST=0.0.0.0` 或 `--host 0.0.0.0`。
2. 非本机来源**必须有令牌**（`X-Exam-Token`，`hmac.compare_digest` 按字节比较）；
   要监听非本机又拿不到令牌时，服务**拒绝启动**（fail-closed），不裸奔。
3. 写入口只开放**记录接入**与**告警接入**；`review_alert` / 远程擦除 / 命令控制台
   **一律不经此端口**（`RemoteTerminal.ROUTES` 里根本没有这些 op）。被拒的访问会写审计链。

**远端记录与本机审计链是分开的（重要）**：`audit` 是本机 `sha256(prev+规范化JSON)` 哈希链，
把别人的记录并进去会立刻校验失败。所以远端记录进 `remote_records` 表（按 `device_id`
分组，落库前逐字段加密），本机链上只写一条回执"收到 X 设备 N 条"。
对端声明的链头哈希存进 `remote_devices`，链头变化会如实留痕 —— 但终端**不能**替对端
校验完整链（只有增量记录，没有全链），所以它报告的是"对端自校验结果"，不是终端验证结论。

### 对外接口（接入服务，供 01/02 与 00 联动层使用）

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 健康与计数（本机免令牌；跨设备需令牌） |
| GET | `/api/status` | 终端状态（告警数/复核数/链校验/远端记录数） |

### 命令台：目标可以填 IPv4（2026-10-18 新增）

现场常见的情况是"只知道对端那台机器的 IP（DHCP 分的），不知道它的计算机名"。
所以「📡 命令台」的目标框现在两种都能填：

| 你填什么 | 会发生什么 |
| --- | --- |
| 设备标识（如 `CAM-A01-1` / 计算机名） | 老用法，原样落库，对端按自己的标识轮询领取 |
| **该设备的 IPv4**（如 `192.168.1.20`） | 先按设备台账（`remote_devices.last_ip`）反查成设备标识再落库，**同时**把 IP 存进 `target_ip` |

对端（`00_集成联动\command_runner.py`）启动时会打印本机 IPv4，并在每次轮询时
带上 `&ip=<本机IP,…>`；服务端按"**设备标识或任一 IP 命中**"派发，所以：

* 你按 IP 下发 → 对端按标识轮询能领到（因为已经反查成标识了）；
* 你按 IP 下发、但台账里还没这台设备的 IP → 对端带 `&ip=` 轮询照样能领到；
* 别的设备按标识轮询领不到（目标隔离不受影响）。

> 前提：那台设备**至少上报过一次记录**（或手动设 `--ip`），终端才知道"这个 IP 是谁"。
> 从没上报过的设备，第一次请让它运行命令执行器（它会带 IP 来轮询）或先在 01/02 里点一次上报。

## 三之二点五、运行模式：考试 / 非考试（教学）（2026-10-18 新增）

这套终端平时也能拿来做**日常教学**（试摄像头、调算法、演示 AI）。但教学不该被
"红色强制确认 / 弹窗 / 超时追责"打断；真考试时又必须回到严格口径。所以做成顶栏一个按钮：

```
顶栏：[🎯 考试模式]（红）  |  [🎓 切到非考试（教学）]      ← 有 maintain 的角色可点
      切换时弹确认框，列出"这次切换会改变什么"；可填切换原因，写入审计链
```

**两种模式的真实差异**（都有代码与测试对应，不是只有文案）：

| 行为 | 考试模式 | 非考试模式（教学） |
| --- | --- | --- |
| 红色预警 | **必须先确认**才能复核 | 可直接复核（结论/理由照样留痕） |
| 红色预警提醒 | **弹窗**（考试期间不许漏看） | 不弹窗，只在列表标红 + 状态栏提示 |
| 新告警留档 | 按考试口径 | 打 `extra.run_mode=teach` 标记，事后可与考试数据区分 |
| 审计链 / 复核留痕 | **照常** | **照常**（不清空、不弱化） |
| 切换动作本身 | 写审计（谁、从什么切到什么、原因） | 同左 |

* 权限：切换需要 `maintain`（所有者/管理员）；其它角色只看到当前模式徽标。
* 存储：`kv['run_mode']`，**默认考试模式**；读不到/写坏了都回落到考试模式（宁严不松）。
* 实现：`runmode.py`（读取/校验/切换/说明）+ `review.py`（复核闸门）+ `alerts.py`（教学标记）
  + `terminal_gui.py`（顶栏按钮/徽标/弹窗闸门）+ `dashboard.py`/`lan_service.py`（驾驶舱与网页显示模式）。

## 三之四、监控查看 UI 优化（2026-10-19）

### 1. 修掉"监控页一大块白板"

**根因**：监控网格用的是 `tk.Canvas` + `tk.Frame`，而 `ttk` 主题**管不到原生 tk 控件**；
旧代码把画布底色写死 `#f4f4f4`、面板写死 `#f9f9f9`，于是在深色终端上监控页会突然
出现一大块浅色底（现场截图里非常明显）。现改为统一取 `theme.py` 的 `BG2/PANEL/FG`，
面板边框也换成主题的绿/橙/红语义色（旧色 `#0a7d28` 在深色底上几乎看不见）。

### 2. 画面放大（用户点一下就要大）

| 交互 | 行为 |
| --- | --- |

放大窗口里显示：人数、越界、密度、分析长边、检测链（含分块数）、逐人行为列表、

## 五、范围说明（**未做**的部分，避免误解）

1. **硬件整机**：国产化 OS（麒麟/统信）、信创整机、三防 PAD、拼接大屏、电子时钟终端 —— 采购事项。
2. **国密算法（SM2/SM3/SM4）**：本目录用 PBKDF2-HMAC-SHA256、SHA-256 哈希链；如验收强制要求国密，
   需替换为硬件密码模块或国密库，属后续改造。
3. **MDM 服务端**：本目录只实现终端侧智能体（收指令、生效、留痕）；MDM 平台需另行部署。
4. **终端准入认证 / 设备指纹 / 防拆开关**：硬件与网络准入层面能力，本目录未实现。
5. **多路视频同时解码**：本目录不做视频解码，视频能力在 01/02 项目与边缘节点。
6. **签到 / 抽签**：手持核验的人脸部分已打通，签到与抽签是业务扩展点，尚未实现。
7. **终端不落地全量视频**（第四节要求）：本目录只保存告警与复核附件，不保存视频流，符合该约束。
8. **命令控制台不做降权隔离**：子进程与本程序同一用户身份；对所有者而言它等价于整机控制权，
   因此**不做（也做不到）命令白名单**——真正的防线是"谁能登录所有者 + 总开关是否打开"。
   所有者口令强度直接等于本机安全性，部署前必须改掉默认口令。管理员那一级有白名单
   （`ollama run`），但那是"能不能下放"的问题，不是"整机是否安全"的问题。
9. **局域网联动只做"接入 + 鉴权"，不做传输加密与设备准入**：接入服务是 HTTP **明文**
   （令牌也只是明文比对），只在**可信考场内网**里用；要跨不可信网络，
   请置于反向代理 + HTTPS 之后，或改用项目三的统一身份认证/国密改造（见第 2、4 条）。
   设备准入、802.1X、终端指纹这些仍属部署层面的能力，代码里没有。
   另外，远端设备上报的记录由**对端负责脱敏**（01 已用 `pii.sanitize_for_log`，
   02/03 的详情本身不含证件号）；终端侧落库时还会再逐字段加密一次。
