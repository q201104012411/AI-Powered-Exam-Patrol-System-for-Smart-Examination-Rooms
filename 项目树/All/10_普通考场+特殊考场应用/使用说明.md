# 使用说明 · 普通考场 + 特殊考场应用

> 面向**考点考务管理员 / 巡考员 / 数据保护专员**的操作手册。
> 想先看"这个模块到底实现了方案里的哪些条目"，请看 [`README.md`](README.md)。

---

## 一、三分钟上手

1. 双击 **`启动考场应用界面.bat`**。
   - **不会出现黑色命令行窗口**（用 `pythonw.exe` 启动）；
   - 如果起不来，会**弹一个对话框**告诉你原因，并把完整堆栈写进
     `data\logs\launch.log`——不会"双击了没反应"。
   - 想先确认环境没问题，先双击 **`启动前自检.bat`**（两关都过再开界面）。
2. 第一次打开是空的：点左边 **`一键演示数据`**，会自动铺好
   **普通 2 个 + 特殊 7 类各 1 个**共 9 个考场（含告警、指标、报告）。
   演示数据全部标注为合成数据，验收时换成现场实测即可。
   - 想要自己的考场：点 **`＋ 新建考场`**，填名称、座位数、
     **启用申请原因**，选考场类型。
3. 左边点中一个考场 → 右边「考场台账」页会显示它的
   **定位说明、能力缺口、相对普通考场的差异项**（差异项最多 26 项）。
4. 切到 **「准入自检」页**，按 ①→②→③→④→⑤ 一路点下去：
   - ① 套模板 + 登记点位（会**同时把点位登记进 02 的机位台账**）
   - ② 机位画质自检（**结论来自专题 02**）
   - ③ 在岗核验 + 座位建模（**只存编号**）+ 逐考场标定
   - ④ 准入自检（给出"可以启用 / 禁止启用"和逐条理由）
   - ⑤ 启用（不通过会被**拦住**，并告诉你缺什么、去哪补）
   - 这些步骤都要**起子进程问 02**，所以放到后台执行：界面上方状态栏会显示
     "正在调用 02/03…"，**界面不会卡住**，你可以继续切页签。
5. 考场变成「已就绪」后，到 **「分级告警」页**试判一次：
   选行为 → 填置信度 → `试判（不推送）` 看定级、推送对象、抑制原因；
   确认没问题再点 `真实上报（送 03）`。

## 二、七个页签分别干什么

### 1. 考场台账

| 按钮 | 作用 |
| --- | --- |
| 套用模板 | 按考场类型一键套用（点位、算法、参数、告警、合规、行为开关） |
| 降级最小可用配置 | 只裁**期望点位**，必需点位一个不删；普通/机考/口试/大教室**不允许**降级 |
| 恢复标准配置 | 回到模板全量点位 |
| 下半屏左 | 实际点位 + 机位编码 + 是否必需 |
| 下半屏右 | **与本考场类型的差异项** + 能力缺口（必需=阻断，期望=建议） |

> 「差异项」是给验收和评审看的：一眼能说清"特殊考场到底特殊在哪"。

### 2. 准入自检

五步流程按钮 + 一排能力开关（非人脸替代核验 / 替代通道演练 / 全离线自检 /
跨机位去重 / 屏幕行为审计 / 覆盖完整性）。开关一改，能力缺口会**立刻重算**。

下半屏输出**逐机位明细**和**阻断项 / 警告项 / 已通过判据**。
`启用（arm）` 会被强制流程拦住——这是方案第五节明确要求的（临时启用最容易漏自检）。

### 3. 分级告警

- 「行为」下拉**只列本考场启用的行为**（无障碍不含纯肢体类，口试不含交头接耳类，
  屏幕行为只在机考考场出现）。
- 「置信度」是你的识别引擎给的分；「机位可信度」是 02 给的画质系数；
  「持续帧数」填 1 会被判为**瞬时动作**并降权 0.7（治"逐帧标签被瞬时动作骗"）。
- 试判结果会写清楚：级别、告警码、推送对象、响应要求、SLA、画质系数、
  **定级说明**（为什么降级 / 为什么抑制）。
- 下面选一条告警 + 结论（成立/不成立/误报）+ 理由 → `提交复核`。
  误报会自动进"算法迭代闭环"。

### 4. 数据分域

- `建立/查看本考场分区`：按考场类型的合规域建物理分区（
  隔离考场 -> 健康信息域、机考 -> 作答内容域、涉密 -> 涉密域）。
- 域 + 角色 → `授权` / `撤权` / `试访问（跨域拦截）`。
- 隔离域**默认拒绝**，必须独立授权；越权访问也会留痕（可审计）。
- 面板下半部分是**域 x 角色授权矩阵**和**合规体检**（谁还不满足强制项）。

### 5. 合规留痕

做 **DPIA**（评估人不能等于操作人）、记录**替代通道演练**（见证人不能等于操作人）、
**全离线自检**、**设置保存期限**（≥ 7 天）、**考试结束封存**、
**到期销毁**（操作人 + 见证人 + 理由，出销毁记录）。

> 销毁是**真删文件**（分区目录里的东西会被清掉），按钮会先弹确认框。

### 6. 验收指标

上半部分是录入框（标注样本总数 / 提示到 / 类别判对 / 误报条数 / 响应秒数 /
在线率 / 覆盖完整性 / 去重真值 / 去重计数 / 时钟偏差），**数据来源**一定要选对：

| 数据来源 | 什么时候用 |
| --- | --- |
| `real` 考场实测 | 真实考试场景跑的，验收就认这个 |
| `synthetic` 合成/演示数据 | 演示、流程验证；**报告里会单列声明，不算真实准确率** |
| `manual` 人工录入 | 会议/评审手工填的 |
| `replay` 历史回放 | 用历史数据回放 |

- `计算并保存指标`：给出 达标 / 未达标 / **缺失** 三分，每一项都带**证据来源**。
  没有证据的项一律写"缺失"，**不填默认值**。
- `用内置基线跑一次（标注为合成）`：快速看流程，不做数的。
- `生成验收报告（md + csv）`：落到 `data\reports\`。
- 下半屏是**考点验收看板**（每个考场达标/未达标/缺失几项）。

### 7. 审计与联动

- `校验审计哈希链`：本模块所有动作（建档/套模板/自检/启用/告警/复核/授权/销毁）
  都在哈希链上，改一条就断链，可自证完整。
- `探联动（01/02/03/06）`：逐个探一遍并显示状态。
- 右下「联动沙箱目录」：填了就**把跨系统调用重定向到那个临时目录**，
  生产环境留空（用各模块真实数据目录）。

## 三、按考场类型的操作要点

| 考场类型 | 必须额外做的 | 不做会被拦 |
| --- | --- | --- |
| 普通考场 | 点位齐、机位在 02 台账、标定、在岗、座位建模 | `QUALITY_UNCHECKED` / `CAMERA_UNREGISTERED` / `CALIBRATION_MISSING` / `ROLE_MISSING` |
| 备用考场 | 允许降到最小可用配置（1 机位 + 1 链路） | 点位低于 `points_min` |
| 隔离考场 | **DPIA** + 远程监考在岗 + 健康信息独立分区 | `DPIA_MISSING` / `REMOTE_INVIGILATOR_MISSING` / `DOMAIN_UNISOLATED` |
| 无障碍考场 | **人工核验工位**（替代通道）+ **演练记录** | `ALT_CHANNEL_MISSING` / `DRILL_MISSING` |
| 机考考场 | **屏幕行为审计** + 双机位 + 作答内容独立分区 | `SCREEN_AUDIT_MISSING` / `DOMAIN_*` |
| 口试考场 | 录音采样率 ≥ 48kHz | `AUDIO_QUALITY_LOW` |
| 大教室 | **跨机位去重已验证** | `DEDUP_UNVERIFIED` |
| 涉密考场 | **全离线自检** + 涉密独立分区 + DPIA | `OFFLINE_UNVERIFIED` / `OFFLINE_UNSUPPORTED` |

> 「不许启用」不是"系统坏了"：每条阻断都会带**具体原因和点位**，修完重跑自检即可。

## 四、常见问题

**Q：机位自检一直说"未登记机位编码 / 不在 02 台账"？**
A：本模块**不自己编造画质结论**。要么在「准入自检」①里登记点位编码
（会同时写进 02 的机位台账），要么先在专题 02 里把机位建好、采好基准图。
不登记就如实判"未检"——这正是方案里"漏检"的根源，不能糊过去。

**Q：画质明明没问题，为什么被降权/红色变成橙色？**
A：02 给的是**该机位最近一次核查结论**的系数（fail ×0.5 / warn ×0.8）。
先在 02 里做一次画质诊断，系数就会回到 1.0。
另外 03 也会在系数 < 0.6 时把红色自动降为橙色，这是链路既有设计。

**Q：告警发不到 03？**
A：先在「审计与联动」页点 `探联动` 看 03 通不通。红色预警在 03 那边
**必须先确认再复核**，本模块会自动先补一次确认（与 03 界面点"确认"同一套留痕）。

**Q：为什么"降级最小可用配置"点了没反应？**
A：只有**备用 / 隔离 / 无障碍 / 涉密**四类允许降级，而且只裁期望点位。
普通/机考/口试/大教室不允许降级——点位不足就得补齐，不能降标准。

**Q：自检会不会把我真实考场的数据弄乱？**
A：不会。`运行自检.bat` / `python 自检.py` 全程用**临时数据目录 + 联动沙箱**。
想核实，跑一次 `检查是否污染其他模块.bat`：它会只读检查 01/02/03/06 的真实库，
其中「来自专题10的告警（应为 0）」必须为 0。

**Q：界面打不开 / 一闪而过？**
A：本模块的启动器已经把常见原因都变成了**弹窗提示**，按提示处理即可：

| 弹窗提示 | 原因与处理 |
| --- | --- |
| `Python 3 with tkinter was not found` | 没装 Python 或没勾 tcl/tk。装 Python 3.10+，勾上 `tcl/tk and IDLE` 与 `Add python.exe to PATH` |
| `启动失败（缺少图形/数据库组件）` | Python 装了但缺 tkinter / sqlite3，同上重装勾选 |
| `启动失败（数据目录不可写）` | 文件夹在只读盘/受保护目录，整个文件夹拷到可写位置 |
| `启动失败（数据初始化失败）` | 数据库被占用或损坏。先确认没有第二个窗口在跑；仍不行就删 `data\rooms.db` 重来 |
| 什么都没弹但没窗口 | 看 `data\logs\launch.log`，里面有完整堆栈；也可双击 `启动前自检.bat` 定位 |

> 启动器还会在 12 秒内拒绝重复开窗（防止双击好几下开出一堆窗口互相抢库）；
> 想强制再开，等十几秒即可。

**Q：界面点一下要等几秒，是卡住了吗？**
A：不是。准入自检要**逐个机位起子进程问 02**（一个考场 4~6 个机位 = 2~6 秒）。
这些动作已经放进后台线程，状态栏会显示"正在调用 02/03…"，**界面保持可用**；
期间再点按钮会提示"上一个任务还在执行"。

**Q：勾了开关但能力缺口还在？**
A：能力分两类：`point`（缺实体点位，去「考场台账」补点位）和 `job`
（还有一件事没做）。`job` 类在缺失时给的提示就是**去哪做**：
演练/离线自检去「合规留痕」页，屏幕审计/去重验证/即插即用/医生协同/日志代理
在「准入自检」页勾选（带双人/理由要求，不能空勾）。

## 五、命令行速查

```bat
:: 启动界面（零黑窗口；等价于双击 启动考场应用界面.bat）
pythonw launcher.py

:: 铺演示数据（9 个考场完整场景；指标标注为合成数据）
python 演示数据.py
python 演示数据.py --sandbox     :: 只验证，不落真实 data\
python 演示数据.py --force       :: 已有考场也继续铺

:: 端到端自检（临时目录，可破坏性测试）
python 自检.py
:: 真实数据目录只读体检
python 自检.py --real
:: 只跑本模块，不碰联动
python 自检.py --nolink
:: 界面无头自检
python 界面自检.py

:: 集成接口（别的专题/脚本调本模块）
python integration_api.py --op status      --args "{}"
python integration_api.py --op templates   --args "{}"
python integration_api.py --op admit       --args "{\"room_id\":\"RMxxxx\",\"operator\":\"考务管理员\"}"
python integration_api.py --op arm         --args "{\"room_id\":\"RMxxxx\",\"auto_register\":true}"
python integration_api.py --op compliance  --args "{}"
python integration_api.py --op report      --args "{\"hours\":720}"
```

> `admit` / `arm` 支持 `"auto_register": false`：默认会把考场点位
> **自动登记进 02 机位台账**（现场本来就是"装机位 → 02 建档"的顺序）；
> 关掉它就只做核验，编码不在台账即如实判 `CAMERA_UNREGISTERED` 阻断。
