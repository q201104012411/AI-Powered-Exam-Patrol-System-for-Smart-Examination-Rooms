# 智能安检与手机作弊器材检测（06）

**事前阻断**：在考点入口把手机、无线耳机、金属作弊器材挡在门外。
02/03 管"事中发现"（摄像头 + 终端处置），本模块管"事前阻断"，报警同样进 03 终端处置。

> 零第三方依赖：只用标准库（tkinter / sqlite3 / http.server）。
> 双击 `启动.bat` 打开界面；**不需要 pip 安装任何东西**。

## 一、快速开始

```
1) 双击「启动.bat」        # 打开界面（无登录；本模块是现场作业工具，权限体系在 01/02/03）
2) 点「⚡ 一键演示」        # 登记 4 类设备 + 开模拟安检门 + 跑样本回放 + 生成演示流程
3) 去「③ 过检与报警」处置几条报警（复检 -> 放行/暂扣/转人工通道/误报）
4) 去「④ 手机保管柜」存一部手机、再取走，看「存取留痕」
5) 去「⑥ 样本测试与验收」点「生成验收证据报告」
```

没有真设备时，一切都能演示（数据来源标 `sim`）；**接上真设备就能直接用**（见第五节）。

## 二、这个模块到底做什么

对着《智能安检与手机作弊器材检测.md》的四个环节落地：

| 环节 | 设备 | 本模块给什么 |
| --- | --- | --- |
| 考点入口安检 | 智能安检门 | 六路感应接入 + **判据引擎**（强度 -> 橙/红报警）+ 过检留痕 |
| 复检通道 | 手持金属探测器 + 人工复检 | 复检派单、SLA 催办、四种处置结论、超时自动上报 03 |
| 手机集中保管 | 智能储物柜 | 柜格台账、人脸/扫码开柜、存取留痕、超时未取、丢失追溯 |
| 鞋底/隐蔽部位 | 鞋底检测仪（可选） | 独立"鞋底"感应通道与样本（**不配鞋底仪就会漏，报告会写明**） |
| 数据联动 | 与身份核验关联 | 过检记录带考生号/座位/考场；报警经 00 联动进 03，形成"人-物-时"闭环 |
| 特殊考生 | 人工安检替代通道 | 孕妇/植入医疗器械登记，**双人见证**强制，一键生成演练记录 |

### 判据引擎（报警怎么判出来的）

安检门把每次过检归一化成六路 0~1 强度：`metal` `magnetic` `phone` `earphone`
`millimeter` `shoe`。判据规则（可在界面「⑦ 设置」里改）：

| 情形 | 结果 |
| --- | --- |
| 全部低于阈值 | **放行**（不产生任何报警） |
| 只有 1 路超阈值 | **橙色报警** + 必须复检（既不放过"单路也能发现的手机"，也不让误报堆积） |
| ≥ 2 路同时超阈值 | **红色报警**（双判据确认，直接进处置队列） |
| 关掉"双判据确认" | 单路也报红（适合已知现场干扰极少的考点） |

阈值模式（整体缩放，用于现场调校）：

| 模式 | 效果 | 内置样本实测 |
| --- | --- | --- |
| `turbo` 快速通行 | 阈值放宽，通行更快 | 误报率升到 **43%**（腰带扣/钥匙串/工牌夹开始报） |
| `standard` 标准 | 默认 | 手机 100%、耳机 100%、误报 0% |
| `strict` 从严 | 阈值收紧，压漏检 | 耳机检出降到 **75%**、作弊整体 82%（漏检换"不误报"） |

> 这三行数字是**内置样本回放**的结果，用来展示"漏检 ↔ 误报"的取舍，**不是**整机实测结论。

### 检出率/误报率是怎么算的（验收口径）

```
检出率 = 应报警且报了 / 应报警样本数      ← 分母来自样本库（ground truth），不是过检总数
误报率 = 无害样本却报警 / 无害样本数      ← 无害样本：腰带扣/钥匙串/眼镜/硬币/纯布衣
```

样本库内置 20 条：手机（开机/关机/鞋内/绑腿）、无线耳机（入耳/充电仓/挂脖/2.4G 模块）、
金属接收器、强磁器材、智能手表；无害物 7 条；**植入医疗器械 2 条**
（起搏器/骨钉 —— 设备**必须响**，但这不是作弊：正确处理是转人工通道 + 双人见证）。

两种测试模式，**分开记账**：

| 模式 | 验什么 | 能不能当验收证据 |
| --- | --- | --- |
| 判据回放 `replay` | 算法与阈值（样本感应值喂给判据引擎） | **不能**，报告里会写明"只验算法与阈值" |
| 现场实测 `field` | 整机（真设备跑真实样本，人工录入报没报） | **能**，这才是验收证据 |

**没有现场实测记录时，报告会明确写「整机实测证据：缺失」**，不拿回放数字糊验收。

## 三、界面七个页签

| 页签 | 干什么 |
| --- | --- |
| ① 总览 | 8 个指标卡片 + 实时过检 + 待处置报警（红在前、超时优先）+ 设备状态 + 运行日志 |
| ② 设备与通道 | 安检门/手持探测器/储物柜/鞋底仪登记、接入、探活；灵敏度可逐台调 |
| ③ 过检与报警 | 报警队列、复检（方式/结论/查获物/见证人）、上报 03、人工录入一次过检 |
| ④ 手机保管柜 | 柜体格位图（绿=空闲/橙=已存/灰=故障）、存入/取走/应急开柜/故障、存取留痕与追溯 |
| ⑤ 特殊考生通道 | 人工安检登记（双人见证硬校验）、替代通道演练记录、上报 03 |
| ⑥ 样本测试与验收 | 样本库、判据回放、现场实测录入、指标（手机/耳机/误报/效率）、生成验收报告 |
| ⑦ 设置 | 考点/操作员/判据模式/六路阈值/双判据开关/上报开关/模拟器参数/字段加密开关/隐藏命令行 |

效率与疏导：通过效率按 5 分钟窗口算 **人/分钟**（指标 ≥20），单通道排队 ≥25 人预警、
≥40 人建议加开备用通道；"安检—核验—签到"三点位串联会算各点位平均耗时并指出**瓶颈点位**。

## 四、数据放在哪

默认本目录 `data\`，可用环境变量 `EXAM_SEC_HOME` 或同目录 `sec_home.txt` 重定向。

| 路径 | 内容 |
| --- | --- |
| `data\security.db` | 13 张表：设备、过检、报警、复检、柜体、柜格、开柜日志、特殊考生、流程、样本、测试运行/明细、审计 |
| `data\security_settings.json` | 设置（考点/阈值/模式/上报开关/字段加密开关…） |
| `data\.data_key` | 字段加密密钥（**已 gitignore，丢了数据就解不回来，请备份**） |
| `data\reports\` | 验收证据报告（Markdown + CSV） |
| `data\samples\样本清单.json` | 样本库导出 |
| `data\logs\security.log` | 运行日志 |
| `data\hide_cmd.on` | 存在则用 pythonw 零黑窗口启动 |

### 敏感字段加密（与 01/02/03 同一套口径）

考生标识（身份证/姓名/准考证/座位）**加密落库**，不是明文：

- 算法 Fernet（AES-128-CBC + HMAC-SHA256），密文带 `enc:` 前缀；
- 密钥取环境变量 `EXAM_DATA_KEY`，否则读/生成 `data\.data_key`；
- **兼容历史明文**：读到不带 `enc:` 的值原样返回，所以开关随时可改，不需要迁移数据；
- **盲索引**：加密后没法用 SQL 等值查考生，所以另存一列
  `candidate_key = sha256("sec06|" + 考生号)`（不可逆）；柜格分配、丢失追溯、"该考生是否已存手机"
  全部走这一列 —— 库里看不到明文，业务上照常查；
- **零依赖不破**：本模块主打只用标准库。没装 `cryptography` 时**不报错也不假装**——
  加密自动降级为明文，界面「⑦ 设置」与验收报告都会写明"当前未加密，仅靠本机文件权限保护"。

> 密钥与数据库同机存放属"静态加密 + 访问控制"级别；生产环境建议把 `EXAM_DATA_KEY`
> 托管到 KMS 并定期轮换（`data_crypto.rotate_key()` 提供轮换接口，需自行迁移旧数据）。

审计是**哈希链**（`prev_hash -> this_hash`），改一条就断链；界面「⑦ 设置」可一键校验。
合规上：过检/报警记录与开柜日志按天保留（默认可清理 30 天前），审计不随清理删除；
报告与追溯默认只显身份证后 4 位。

## 五、设备接入协议（接真设备）

三种真入口，**接上就能用**；用 `python 工具_设备联调.py --device GATE-A01 --port 9106`
可以先在本地把通路跑通（真设备往这里推，屏幕实时打印）。

| 接入方式 | 设备侧怎么做 | 说明 |
| --- | --- | --- |
| HTTP 行协议 | `POST http://<本机IP>:<端口>/api/pass`，body 一行 JSON | 探活 `GET /health` |
| TCP 行协议 | 连上 `<本机IP>:<端口>`，丢一行 JSON（telnet 风格） | 发 `health` 可探活 |
| 串口行协议 | 串口一行 JSON（需 `pip install pyserial`） | 没装 pyserial 会**如实报错**，不假装在收 |
| 内置模拟器 | 不用设备 | 数据 `source=sim`，**不计入检出率** |
| 人工录入 | 复检重过门 / 演练 / 无设备时 | 数据 `source=manual` |

报文格式（`sensors` 也可平铺在顶层，字段能少不能错）：

```json
{"device_code":"GATE-A01","candidate_id":"2026...","candidate_name":"张三",
 "seat_no":"07","room_id":"1考场","duration_ms":820,
 "sensors":{"metal":0.71,"magnetic":0.20,"phone":0.05,
            "earphone":0.02,"millimeter":0.10,"shoe":0.03}}
```

真机联调三步：
1. `python 工具_设备联调.py --device GATE-A01 --proto http --port 9106` 起接收端；
2. 安检门侧把上报地址配成 `http://<本机IP>:9106/api/pass`；
3. 让考生过一遍，界面「① 总览」会实时出过检与报警；调不通就用
   `python 工具_设备联调.py --send http://<本机IP>:9106/api/pass` 反着验一次。

> 真机数据一律 `source=real`，与模拟数据在库里、界面上、报告里都分得清。

## 六、与其它模块怎么联动

```
06 安检判据出报警
   ├─ 手机/无线耳机            -> PHONE_DETECTED（红）  ┐
   ├─ 金属/强磁/鞋底           -> SECURITY_ALARM（橙）  ├─> 00_集成联动 -> 03 智能终端
   ├─ 复检超时未处置           -> SECURITY_REINSPECT_TIMEOUT（橙）      （分级展示 + 复核留痕）
   ├─ 保管柜超时未取           -> LOCKER_ABNORMAL（橙）  ┘
   └─ 特殊考生转人工通道       -> SECURITY_SPECIAL_CHANNEL（橙）
```

- 默认**不实时推**（避免每次报警都刷屏 03）；界面「③ 过检与报警」可逐条手动上报，
  或在「⑦ 设置」打开"报警实时上报 03"。
- 上报走 `linkage_bridge.py` -> `00_集成联动` -> 03（每套的 integration_api.py 子进程隔离），
  03 不在或报错**不影响安检继续跑**（返回 None 并记日志）。
- 反向也通：00 的 `Linkage.security_pass()/security_status()/security_reinspect()`
  可以直接驱动本模块（`python 00_集成联动/main.py` 已把"06 报警进 03"纳入端到端自检）。
- 09 无障碍/特殊考生保障与此互补：本模块提供人工安检替代通道的**记录与演练留痕**。

## 七、自检

```bat
双击「运行自检.bat」          :: 或 python 自检.py      → 152 项，临时目录，随便跑
python 自检.py --real         :: 用真实 data 目录只读检查
python ..\00_集成联动\main.py  :: 端到端联动自检（32 项，含 06 -> 03）
```

自检覆盖：判据引擎（阈值/灵敏度/模式缩放/双判据）、设备台账与探活、过检与报警派单、
复检处置（操作人必填、结论白名单、重复处置拒绝、查获自动入柜）、保管柜（重复占用拒绝、
错人开柜拒绝、应急开柜须写理由、故障格保护、超时扫描、丢失追溯）、特殊考生双人见证、
三点位顺序校验与效率/瓶颈、样本与检出率（含"故意漏检一条，检出率如实下降"）、
HTTP/TCP 真起服务收报文、报告落盘与"无实测时写缺失"、**敏感字段密文落库 + 盲索引查询**、
审计哈希链篡改可检出、联动沙箱（**自检不往 03 真实库写测试告警**）。

## 九、注意事项与如实说明

1. **没有真设备时，一切数字都是模拟/回放的**：界面与报告都会写明来源，
   验收请务必用「现场实测」跑一遍真设备。
2. **鞋内藏匿需要鞋底检测仪**：不配这一路，鞋内手机会漏（样本 SP-B03 就是验这个前提）。
3. **无线耳机信号弱**：样本 SP-B07 只有 0.55，贴着阈值 —— 所以本模块用
   "单路报橙 + 复检兜底"，而不是把阈值调低到满屏误报。
4. **植入医疗器械报警不算误报**：设备本来就该响；处理是转人工通道 + 双人见证，
   并提醒考生今后主动申报、不要过安检门。
5. **保管柜扣的是"物品信息"**：只记录手机型号/数量这类必要信息，不采集手机内容；
   开柜人与登记考生不一致时**拒绝**人脸/扫码开柜，只能管理员应急开柜并写理由。
6. **本模块不做人脸比对**：考生身份来自 01 人脸核验或现场录入的考生号；
   要做"人证一致再安检"，把 01 的核验结论带进过检记录即可（字段已留）。
7. 本模块**不落安检图像**：只存感应强度与结论，没有隐私画面。
8. **考生标识加密**：装了 `cryptography` 就自动加密落库（密文 + 不可逆盲索引）；
   没装则明文落库，界面与报告都会写明——**不会假装加密**。
