# 12 告警上传与终端处置演示

把这条链**真跑一遍**（不是画流程图）：

```
02 摄像头核查与视频质量诊断
   │  诊断现场画面 -> 得出缺陷 + 画质可信度 credibility
   │
   ├── 上传告警（含画质可信度） ──────────────► 03 智能终端操作
   │                                              │  接入（分级 / 去重 / 进补传队列 / 写审计）
   │                                              ▼
   │                                     待处置 pending
   │                                        │ 确认 ack（红色预警强制）
   │                                        ▼
   │                                     已确认 acked
   │                                        │ 复核 review（结论 + 理由 + 见证）
   │                                        ▼
   └──────────────────────────────────  已复核 reviewed（哈希链留痕）
```

演示脚本不做以下事情，**全部走两个系统自己的实现**：

| 环节 | 真正在跑的代码 |
| --- | --- |
| 画质诊断、缺陷分级、可信度降权 | `02/config.py`、`02/diagnose.py`、`02/patrol.py` |
| 告警上报通道 | `02/integration_api.py` → `03/integration_api.py`（子进程 + JSON） |
| 告警分级 / 去重 / 补传队列 / 审计 | `03/alerts.py`、`03/offline.py`、`03/storage.py` |
| 确认 / 复核 / 留痕 / 误报闭环 | `03/review.py`、`03/models.py` |
| 角色权限与可见考场 | `03/access.py`、`03/config.py` |

## 快速开始

### 桌面 UI + 局域网接收（推荐）

双击 **`启动界面.bat`**（或 `python gui.py`）：

- **上传告警**：填告警码/设备/考场/详情，点「上传到 03」；03 的 `integration_api.py`
  真正写入，随后可在「03 最近告警」看到。
- **局域网接收**：在「局域网接收」页点「启动接收」，默认监听 `0.0.0.0:5030`；
  同一局域网的电脑/手机浏览器打开 `http://<本机IP>:5030/` 即可填表上传，
  上传结果和 03 最近告警在同一页可见。可设访问令牌；Windows 防火墙需放行端口。
- **03 最近告警**：只读回显，确认/复核仍到 03 智能终端「告警处置」完成。

### 命令行演示

双击 **`运行演示.bat`**，或在命令行：

```bat
cd /d "项目树\All\12_告警上传与终端处置演示"

```

跑完会打印每个场景的逐步结果、03 的全过程留痕、审计链完整性，以及检查点汇总。
**退出码 0 = 全部检查点通过。**

自检（单元层 + 端到端层）：

```bat

```

## 五个场景

| 场景 | 演示什么 | 关键断言 |
| --- | --- | --- |
| **A 常规闭环** | 02 出 warn 级画质问题并上传，03 接入后直接复核「成立」 | 状态走到 `reviewed`，复核留痕有 ID |
| **B 强制确认** | 上传红色预警，**先试着跳过确认直接复核**，再走正常流程 | 跳过被拦；自动补确认后复核成功 |
| **C 红转橙** | 让 02 真判出 fail（画质可信度 ×0.5），再上传红色告警 | 03 自动降为橙色待复核；复核为「误报」后进入算法迭代闭环 |
| **D 去重** | 同考场+座位+告警码在 60 秒内上传两次 | 第二次不产生新告警 |
| **E 权限最小化** | 用监考员 `inv01` 去复核 | 被拒（监考员不能自己判自己） |

### 场景 C 为什么重要

画质差的机位会持续产出"疑似手机""疑似多人"这类告警。如果照单全收，
终端会被误报淹没。所以 02 会给出该机位的**画质可信度系数**：

```
有 fail 级缺陷 -> ×0.5     仅 warn 级 -> ×0.8     正常 -> ×1.0
```

03 收到 **可信度 < 0.6 的红色告警**时自动降为橙色待复核，并在告警详情里注明原因
（`03/integration_api.py` 的 `DOWNGRADE_BELOW`）。演示里可以亲眼看到
`降级=True 当前级别=橙色预警`，审计里也留了 `预警降级` 一条。

## 数据安全（重要）

**默认在沙箱里跑**：02/03 的数据目录都会被重定向到

```
12_告警上传与终端处置演示\data\_demo_sandbox\02\
12_告警上传与终端处置演示\data\_demo_sandbox\03\
```

跑完自动清理。真实运行数据（`03_智能终端操作\data\terminal.db` 等）**不会被碰**。

`terminal_console.py` 里有一道 `assert_sandbox()`：万一数据目录被指到 03 的真实
`data\`，演示会直接拒绝启动，而不是"先跑起来再说"。

需要保留沙箱数据来人工翻看：`python demo_main.py --keep`。

要真的写进真实数据目录（一般不需要）：

```bat
python demo_main.py --no-sandbox --yes
```

## 命令行参数

| 参数 | 说明 |
| --- | --- |
| `--scenario A` | 只跑指定场景（可重复：`--scenario A --scenario C`） |
| `--keep` | 跑完保留沙箱数据目录 |
| `--home <目录>` | 指定沙箱根目录 |
| `--operator patrol1` | 处置身份，取 03 预置账户：`patrol1` / `admin` / `owner` |
| `--no-sandbox --yes` | 写真实数据目录（危险） |
| `--quiet` | 不打印横幅 |
| `--list-interp` | 只打印用到的解释器与接口路径 |

依赖：Python 3.10~3.13，装 `opencv-python`、`numpy`
（顺带会用 03 自带的 flask 无关模块；不需要摄像头、不需要联网）。

## 与 00_集成联动 的分工

- `00_集成联动\linkage.py` 是**多系统总线**（01/02/03/06 互相调），偏集成自检。
- 本演示只聚焦 **02 → 03 的告警上传与处置闭环**，把每一步的中间结果、03 的
  强制确认约束、红转橙降权、误报闭环都摊开给你看。
- 上传通道两边是**同一套** `integration_api.py`，所以演示通了，说明真实联动也通。

## 已知边界（如实标注）

- 画面是**合成的**（棋盘图 + 模糊），用来说明 02 的判据与阈值，不代表真实考场画质。
- 处置身份用的是 03 的预置账户（`patrol1` / `admin` / `owner`），口令为演示口令。
- 演示不覆盖"断网补传"的实网回传：`Outbox` 只入队并落 `outbox.ndjson`，
  补传需要配 `EXAM_PLATFORM_URL` 才有对端可打。
