2.1 做了什么（对着《智能安检与手机作弊器材检测.md》的四个环节落地）
  · 判据引擎（gate.py）
      - 安检门六路感应：金属 / 磁场 / 手机特征 / 无线耳机特征 / 毫米波 / 鞋底，归一化成 0~1；
      - 规则：全部低于阈值 -> 放行；只有 1 路超阈值 -> 橙色报警 + 必须复检；
              ≥2 路同时超阈值 -> 红色报警（双判据确认）；可关闭双判据（单路直报红）；
      - 阈值可在界面调，另有 turbo / standard / strict 三档整体缩放（现场调校用）。
  · 设备接入（gate.py + 工具_设备联调.py）
      - 真入口三种：HTTP 行协议（POST /api/pass，GET /health 探活）、TCP 行协议、串口行协议
        （没装 pyserial 会如实报错，不假装在收）；
      - 内置模拟器（数据来源一律标 source=sim）、人工录入（复检重过门 / 演练用）；
      - 工具_设备联调.py 可在接真设备前先验证通路（收 / 发两种模式）。
  · 复检与处置（reinspect.py）
      - 复检必须记操作人；结论白名单：放行 / 暂扣 / 转人工通道 / 误报 / 重复过检；
      - SLA 催办（默认 60 秒），超 180 秒未处置自动上报 03 智能终端；
      - 查获器材**自动分配保管柜格**（人-物-时闭环）。
  · 手机集中保管（locker.py）
      - 柜体/柜格台账、人脸/扫码/证件/应急开柜、存取留痕、超时未取提醒、丢失追溯；
      - 开柜人与柜内登记考生不一致 -> 拒绝人脸/扫码开柜，只能管理员应急开柜并写理由；
      - 已存手机的柜格不允许直接报故障（避免手机被锁死在故障格里）。
  · 特殊考生人工安检通道（special.py）
      - 孕妇 / 植入医疗器械 / 残障 / 医嘱 等；**双人见证硬校验**（见证人不能与主检人相同）；
      - 一键生成"替代通道演练记录"（drill=True，报告里与真实事件分开计数）。
  · 入场效率与流程（flow.py）
      - 安检-核验-签到三点位串联，顺序不对会被拦；各点位平均耗时 + 瓶颈点位；
      - 通过效率按 5 分钟窗口算"人/分钟"（指标 ≥20）；排队 ≥25 预警、≥40 建议加开备用通道。
  · 验收证据（samples.py + report.py）
      - 内置样本库 20 条：手机（开机/关机/鞋内/绑腿）、无线耳机（入耳/充电仓/挂脖/2.4G 模块）、
        金属接收器、强磁器材、智能手表；无害物 7 条；**植入医疗器械 2 条**；
      - 两种测试模式分开记账：判据回放（验算法与阈值）/ 现场实测（验整机，人工录入报没报）；
      - 报告 Markdown + CSV：指标达成、设备、过检与处置、效率与瓶颈、保管柜、特殊考生、
        阈值模式对比、测试记录、审计、如实说明（共十章）。
  · 数据与合规（storage.py + data_crypto.py）
      - SQLite 13 张表 + 哈希链审计（改一条即断链，界面可一键校验）；
      - 考生标识字段（身份证/姓名/准考证/座位）Fernet 加密落库，密文带 enc: 前缀、兼容历史明文；
      - 加密后没法用 SQL 等值查考生，故另存**不可逆盲索引 candidate_key**，
        柜格分配 / 丢失追溯 / "该考生是否已存手机"照常可查；
      - 没装 cryptography 时自动降级明文，并在界面/报告/自检里**如实写明未加密**（不假装加密）。
  · 界面（app.py，七页签）
      ① 总览 ② 设备与通道 ③ 过检与报警 ④ 手机保管柜 ⑤ 特殊考生通道 ⑥ 样本测试与验收 ⑦ 设置
      含「⚡ 一键演示」：登记 4 类设备 + 开模拟安检门 + 跑样本回放 + 生成演示流程。

2.2 口径纪律（写进报告第十章，避免拿好看数字糊验收）
  · 检出率 = 应报警且报了 / 应报警样本数（分母来自样本库 ground truth，不是过检总数）；
  · 误报率 = 无害样本却报警 / 无害样本数；
  · 植入医疗器械报警**不算误报**（设备本就该响，处理是转人工通道 + 双人见证）；
  · 判据回放 ≠ 整机实测：没有现场实测记录时，报告明确写「整机实测证据：缺失」；
  · 模拟器数据 source=sim 在库、界面、报告里都与真机数据分开计数；
  · 鞋内藏匿必须配鞋底检测仪，报告不会把这一条算成"已覆盖"。

五、收尾修复：06 的 ID 偶发撞号（提交 8d9bbca）
--------------------------------------------------------------------------------
  · 现象：06 自检偶发报「现场实测只落了 5 条（应为 6 条）」；
  · 根因：短 ID 生成用"时分秒 + 4 位随机数字"，同一秒内连续录入多条时偶发撞号，
    撞号被 INSERT OR REPLACE 覆盖，表现就是"少了一条记录"（约 1% 量级，属偶发丢数据）；
  · 修复：随机位改为 6 位 hex（models.new_id），碰撞概率可忽略，ID 仍可人工口头报号；
  · 验证：自检连跑 3 次均 152/152 全绿，GUI 冒烟仍 44/44。
