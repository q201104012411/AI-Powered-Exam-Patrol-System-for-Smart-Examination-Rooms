## 1. 为什么"优化"不是换个颜色：先量了一遍旧驾驶舱

改造前的驾驶舱截图里就能看到问题，但真正的原因要量尺寸：

```
驾驶舱 Tab 可视高度：723 px
驾驶舱 内容需求高度：1037 px          <-- 差的 314 px 就是被裁掉的部分
  顶栏 43 · KPI 两行 176 · 图表 227 · 明细+模块 282 · 页脚 23
```

**结论：明细表（最近告警 / 远端设备台账）与页脚整块在可视区之外，被 pack 静默裁掉。**
这不是"没数据"，是**画在窗口外面**——所以以前看截图"好像只有上半屏"。

顺带量出 5 个同源问题（都在下面逐条给修法）：

| # | 问题 | 为什么以前没被发现 |
| --- | --- | --- |
| 1 | 内容溢出被裁切 | 截图只截到上半屏，看着像"设计如此" |
| 2 | 图表只在刷新时画一次，**缩放/全屏后图元停在旧坐标** | 不缩放窗口就看不出；定时器 5 秒后又会重画，掩盖了问题 |
| 3 | 跨模块聚合在**主线程**串 8 个子进程（首轮约 1.8 s） | 只在切到驾驶舱瞬间卡一下，被当成"加载慢" |
| 4 | KPI 用 `list_alerts(limit=2000)` 自己数，**超过 2000 条就偏小** | 演示库只有几十条，永远触发不到 |
| 5 | 每次刷新读 10 万条审计 + 全量验链 | 演示库审计才 1600 条，毫秒级，看不出来 |
| 6 | 文档写"Esc 返回"，**其实没绑定 Esc** | 全屏按钮还在，点按钮也能退，没人去按 Esc |
| 7 | 全屏只是放大窗口，应用顶栏 + AI 面板仍占地 | 认为"全屏就是把窗口最大化" |

## 2. Py GUI 驾驶舱：逐条修法

### 2.1 布局重排 + 滚动兜底（问题 1）

```
row0 顶栏（标题 / 审计链 / 时钟 / 刷新 / 全屏）+ 顶部警戒线
row1 KPI 单行 10 块（磁贴化，高度 176 → 78）
row2 图表区（weight 3，min 205）：分级环形 | 趋势面积图 | 类型 TOP
row3 明细区（weight 2，min 205）：最近告警 | 远端设备 | 全系统模块态势
row4 页脚（数据库 / 账号 / 远端最近接收 / 刷新耗时 / 时间）
```

* 外覆 `theme.VScroll`：**装得下按权重铺满，装不下能滚**——任何窗口尺寸都不丢内容；
* 实测 1180×820：内容 592 px / 可视 707 px，无滚动条；缩到 1000×620 自动出现滚动条。

### 2.2 图表随尺寸重绘（问题 2）

三个画布统一 `<Configure>` → 合并 120 ms 后重绘；`_canvas_size()` 在未布局（宽高 < 60）时跳过一次绘制，
避免"首帧画在 1×1 画布上"。冒烟里直接断言：窗口 1180→1500，折线图最右图元 **x 332 → 425**。

### 2.3 跨模块聚合移出主线程（问题 3）

```
refresh_modules()  ──起线程──►  ModuleStatus(ttl=30, timeout=8).all()
        │                                   │
        └── 立即返回（实测 0.000 s）          └── 结果写 _mod_pending
_tick()（主线程）── 回填表格 ── 只动 Tk 控件，子线程绝不碰界面
```

另外：驾驶舱不可见（切到别的页签）时**不查库不绘图**，切回来立刻补刷。

### 2.4 计数改走 SQL 聚合（问题 4、5）

新增 `storage.stats(hours, days, recent)`：一次调用返回
`total / by_level / by_status / reviews / unsynced / overdue / last_hour / audits /
by_code / hourly / daily / recent`，全部用 `COUNT` 与 `GROUP BY`。
**好处**：① 数字不再受"最多看 2000 条"影响；② 不再把 10 万条审计读进内存；
③ 小时桶/天桶在 SQL 里对齐到整点与本地 0 点，趋势图标签对得上。

审计链全量校验是 O(全表)，从"每 5 秒"降到 **20 秒 TTL**；审计条数每次仍取真实 COUNT。

### 2.5 Esc 与真正的全屏（问题 6、7）

* 进全屏：`root.bind("<Escape>", ...)`，退出全屏自动 `unbind`；
* 进全屏同时**收起应用顶栏与 AI 面板**（页签保留，好切页），退出时 `pack(before=...)` 按原位置放回；
* 大屏下 KPI 数字 20 → 26 px。

> 这里踩到一个真坑并写进了注释：判断"要不要收"**不能**用 `winfo_ismapped()`——
> AI 面板在 1180×820 下本来就被 pack 挤出可视区（未映射），一进全屏反而露出来。
> 现在收的时候无条件 `pack_forget()`，放回的时候无条件重新 `pack`。

### 2.6 视觉：警戒线与"大屏感"

* 标题下一条 3 px 警戒线：无红色预警是暗描边，**有红色预警变红并每秒呼吸**；
* 环形图中心显示总数，图例带数量与占比（占比由真实数据算出，分母 0 显示"—"不编 0%）；
* 趋势图：好刻度（1/2/5×10^k，不再出现 0/1/1/0 这种重复标签）、面积渐变、末点与峰值标注、悬停气泡；
* 类型 TOP：按告警码**中文名**排行，末端高亮块；无数据显示"暂无告警记录"。

### 2.7 顺带揪出一个"有数据就登录崩溃"的原缺陷（重点）

用一份带 15 条复核记录的演示库跑驾驶舱时，**登录直接抛异常、主界面构建中断**：

```
File "terminal_gui.py", line 3066, in refresh_reviews
    r["created_at"], r["review_id"], r["operator"],
TypeError: 'ReviewRecord' object is not subscriptable
```

* 根因：`storage.list_reviews()` 返回的是**解密后的 `ReviewRecord` 对象**，
  而 `review.Reviewer.review_rows()` 原样透传，界面按 `r["created_at"]` 这种**字典**方式取字段；
* 影响：**只要库里存在任意一条复核记录**，登录时 `refresh_all()` 就崩，主界面起不来；
* 为什么长期没被发现：仓库里随附的 `data\terminal.db` 复核表是**空的**，
  空列表不进循环 → 不报错；所有自检/冒烟用的也都是空复核表。**空数据把功能缺陷藏住了**；
* 修法：`review_rows()` 统一转成字典行（界面要的 8 个字段全给齐），
  并补两条回归测试（有记录 / 无记录），断言"返回的是 dict 且字段齐全"。

> 同类的"空数据掩盖缺陷"这个项目里已经出现过一次（13 的 `level` 从不赋值 → 永不报警，
> 51 项自检也没覆盖）。这次的教训同样写进了测试：**用带数据的库跑一遍**，
> 所以本轮的驾驶舱截图/冒烟都用演示库（72 条告警 + 15 条复核）而不是空库。

## 3. 网页版驾驶舱（新增）

### 3.1 为什么放在 03 的局域网服务上

03 只有 `lan_service.py` 一个监听口（默认 9113）。网页大屏要跟 GUI 看同一份数据，
再起一个 Flask 服务既多一个端口、又多一套鉴权。所以直接复用：

| 路径 | 内容 | 鉴权 |
| --- | --- | --- |
| `GET /` | `web\cockpit.html`（单文件、零外部 CDN） | 不鉴权（页面本身不含数据） |
| `GET /api/cockpit` | 一屏要的全部数据（KPI + 两套分桶 + 明细 + 设备 + 8 个模块） | **同既有令牌** `X-Exam-Token` |

页面顶部「⚙ 连接」可改服务地址与令牌（存 localStorage）；跨设备访问由令牌把关，
CORS 只对 `file://`（Origin=null）与 127.0.0.1/localhost 回显 —— 与令牌是两道独立的门。

### 3.2 页面做了什么

* 单文件、**零外部依赖**：图表是原生 Canvas 2D 画的，字体用系统字体（考场内网通常出不去公网，
  任何 CDN 都会让大屏白屏或卡 8 秒）；自检里用正则确认"没有真的外链"（注释里提到 CDN 不算）；
* 与 GUI 同一套配色变量（`--ck-*`），KPI 数字**补间动画**（620 ms）、环形**扫入**（760 ms）、
  条形**生长**（650 ms）；
* 有红色预警：红色 KPI 磁贴呼吸 + 顶栏压一条红色警戒线；
* 每 5 秒自动刷新；**标签页不可见时不刷**（`document.hidden`）；
* 三档自适应：≥1181 px（三列图表 + 三列表格）/ ≤1180 px（2×2）/ ≤720 px（单列）；
  窗口高度不够时 `main` 内部滚动，顶栏与页脚**始终在位**；
* 取不到数据如实显示"暂无数据 / 无法连接 / 需要令牌"，绝不画假数。

> 图表动画的坑：一开始用 CSS transition 与 `requestAnimationFrame` 做补间，无头截图里
> 永远是首帧（条宽 0、环形空）。这类环境一旦上线就是"大屏全是空图"的致命观感，
> 所以统一改成 **`setInterval` + `Date.now()`** 的补间：任何渲染器都能在 650 ms 内收敛到终值。

### 3.3 怎么用

| 你要做的事 | 操作 |
| --- | --- |
| 本机看大屏 | 双击 `03_智能终端操作\启动网页驾驶舱.bat`（自动打开浏览器），按 F11 |
| 局域网另一块屏 | 服务监听填 `0.0.0.0`，浏览器访问 `http://<本机IP>:9113/`，页面「⚙ 连接」里填令牌 |
| 只看数据 | `GET /api/cockpit`（带 `X-Exam-Token`）；`?modules=1` 强制重刷模块态势 |
| 自检 | `python lan_service.py --selfcheck`（21 项，含页面与接口） |

## 8. 追加：命令台支持"按设备 IPv4 下发"（2026-10-18）

**需求**：现场常常只知道对端那台机器的 IPv4（DHCP 分的），不知道它的计算机名/设备标识；
按标识下发就会"发出去没人领"。

**做法（两侧各改一处，任一侧命中都算它）**

| 侧 | 改动 |
| --- | --- |
| 03 存储 | `remote_devices` 加 `last_ip`（含老库迁移）；`save_remote_batch(client_ip=…)` 记下来源 IP；新增 `normalize_ipv4()` / `device_by_ip()` |
| 03 命令队列 | `push_target_command(..., target_ip=)` 把 IP 单独存进 payload；`commands_for(target, ips=…)` 按"**标识或任一 IP**"精确匹配 |
| 03 服务 | `POST /api/command` 收到 IP 时**先反查成设备标识**再落库（查不到就保留 IP）；`GET /api/command` 支持 `&ip=a,b`（多网卡） |
| 03 命令台 | 目标框可填 IP；新增「已知设备」下拉框（点选自动填该设备最近上报的 IPv4）+ 刷新按钮；台账「目标」列同时显示标识与 IP |
| 设备端 | `command_runner.py` 自动探测本机 IPv4（可用 `--ip` 覆盖），每次轮询带上 `&ip=…`；启动时打印本机 IP |

**归一化**：`192.168.1.20:9113` / 带空格 / 前导零都会被规范或拒绝，
避免"看着像 IP 但字符串对不上"导致命令发丢。

**实测**（`lan_service.py --selfcheck` 21 → **26 项**）

```
PASS 设备台账记录来源 IPv4（供按 IP 下发用）      — device_by_ip -> CAM-A01-1
PASS 按 IPv4 下发命令：自动反查成设备标识         — target=CAM-A01-1 ip=192.168.1.20
PASS 对端用设备标识轮询能领到「按 IP 下发」的命令   — 领到 1 条
PASS 台账里没有的 IP 也能被该 IP 的设备按 ip= 领走 — target_ip=192.168.1.99
PASS 别的设备按标识轮询领不到这条（目标隔离）
```

**边界**：按 IP 下发要求"台账里记的 IP 与那台机器现在的 IP 一致"；
换 IP 后以它**最新一次上报**为准，否则请改填设备标识。这条也写进了 `00_集成联动\README.md`。

### 9.1 「无法手动填 IPv4」——是入口设计把人误导了

原来的做法：目标框右边紧跟一个 **readonly 下拉框**（"已知设备"）。它长得像输入框，
点进去却只能选、不能打字，于是"手动填 IP"看起来根本填不进去。

改法：**目标框回归普通输入框**（`state=normal`，宽度加大，旁边写明"可直接手打 IP"），
设备选择改成独立的「📋 从已知设备选…」弹窗（列表双击即填），两者互不干扰。
实测（`logs\_probe\probe_manual_ip.py`）：

```

提示: 已下发 CMD407a7029ac84 → 10.20.30.40（按 IPv4 定位…）

按 ip 能领走: [('CMD407a7029ac84', '10.20.30.40', '10.20.30.40')]
```

顺手修了两个小问题：同一秒内下发的多条命令按 `created_at` 排序会乱序（加 `rowid DESC` 兜底）；
`target` 与 `target_ip` 相同的时候台账会显示成 `10.20.30.40 · 10.20.30.40`（改成只显示一次）。
